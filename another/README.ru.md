# Another VPN

> **Читать на других языках:**  
> [English](README.md) | [Русская версия](README.ru.md)

**Another VPN** — это приватный, кроссплатформенный сетевой стек и система обхода блокировок (DPI), спроектированная с использованием модели **Zero-Knowledge идентификации устройств**, **постквантовой гибридной криптографии** и **собственного легковесного userspace TCP/IP стека**.

Архитектура проекта построена по принципам Hexagonal Architecture (порты и адаптеры) в рамках полиглот-монорепозитория (Go, TypeScript/Cloudflare Workers, Python/FastAPI, Flutter/Kotlin).

---

## Ключевые архитектурные особенности

* **Собственный Userspace TCP/IP стек на чистом Go (`netstack`)**:
  * Не использует сторонние тяжелые зависимости (gVisor, lwIP).
  * Напрямую перехватывает L3 IPv4-пакеты из виртуального TUN-интерфейса.
  * Реализует конечный автомат TCP: генерация SYN-ACK в ответ на SYN операционной системы, отслеживание номеров Seq/Ack, флагов (PSH, ACK, FIN, RST) и размера скользящего окна (Window).
  * Транслирует локальные соединения в исходящие VLESS-потоки.
  * Прозрачно перенаправляет UDP DNS (порт 53) в потоковый TCP:53 (позволяет туннелировать трафик через среды без поддержки UDP, такие как Cloudflare Workers).
* **Сетевые протоколы с нулевыми внешними зависимостями (Zero-Dependency)**:
  * **RFC 6455 WebSocket клиент (`wsproto`)**: Написан с нуля поверх `net.Conn` без сторонних библиотек (ручное маскирование фреймов клиентом, расчет `Sec-WebSocket-Accept`, обработка Ping/Pong/Close).
  * **Протокол VLESS v0 (`vlessproto`)**: Независимая реализация бинарного wire-формата для клиента и origin-прокси.
  * **XTLS Reality (клиент и сервер)**:
    * Клиент использует `utls` для мимикрии TLS ClientHello под Google Chrome с инъекцией Ed25519 в схему подписей.
    * Шифрование сессионных параметров через X25519 ECDH + HKDF-SHA256 + AEAD (ChaCha20-Poly1305 / AES-GCM) внутри поля `SessionID`.
    * Сервер `reality-origin`: проверка подлинности через HMAC в сертификате; при несовпадении ключа — прозрачный fallback-прокси на легитимный сайт-донор (активное зондирование цензором видит обычный сайт).
  * **Split-HTTP (`xhttp`)**: Полнодуплексный туннель через два независимых HTTP/2 запроса (длинный POST для uplink, длинный GET для downlink).
* **Гибридная постквантовая криптография (ADR 0006)**:
  * **Идентичность устройств**: Связка классического `Ed25519` со стандартизированным NIST постквантовым алгоритмом **ML-DSA-65 (FIPS 204)** через библиотеку `circl`.
  * **Панель оператора (Admin Plane)**: Команды подписываются двойной подписью (Ed25519 + ML-DSA-65) и фиксируются в строгой хэш-цепочке с контролем порядкового номера (`seq`), что исключает replay-атаки и разветвления состояния без использования блокчейна.
* **Идентификация устройств Zero-Knowledge**:
  * Приватные ключи генерируются на самом устройстве при первом запуске и никогда не покидают локальный KeyStore (права `0600`).
  * На сервер в процессе онбординга (TOFU) передаются только публичные ключи в обмен на одноразовый инвайт-токен.
* **Многоуровневая маршрутизация и Failover**:
  * **Tier 1 (Bootstrap)**: Бессерверные CDN-точки входа (Cloudflare Worker WebSocket-прокси через `cloudflare:sockets`).
  * **Tier 2 (Target)**: Высокоскоростные выделенные серверы (VPS с Reality или Split-HTTP).
  * Автоматический RTT-пробник узлов и прозрачное переключение при деградации точки входа.
* **Системные TUN-драйверы и Kill Switch**:
  * **Windows**: Динамическая линковка `wintun.dll` через системные вызовы Win32 (`syscall.LazyDLL`, `unsafe.Pointer`); маршрутный blackhole Kill Switch.
  * **Linux**: Нативный `/dev/net/tun` через `ioctl`; атомарное управление правилами фильтрации в `nftables`.
  * **Android**: Интеграция с Android `VpnService` через связку Kotlin и `gomobile`.

## Структура репозитория

```text
├── core/                   # Ядро на Go 1.24 и сетевые sidecar-демоны
│   ├── cmd/
│   │   ├── desktop/        # Фоновый сервис для десктопа (Loopback HTTP API: 127.0.0.1:47821)
│   │   ├── mobilelib/      # Биндинги gomobile для Android/iOS
│   │   ├── reality-origin/ # Автономный сервер Reality и утилита проверки доноров
│   │   └── xhttp-origin/   # Сервер Split-HTTP
│   └── internal/
│       ├── adapters/       # Драйверы TUN, Kill Switch, Netstack, Транспорты, Хранилища ключей
│       ├── app/            # Use Cases приложения (Connect, Disconnect, SwitchNode)
│       └── domain/         # Чистые сущности, гибридная идентичность, политика отказоустойчивости
├── edge/                   # Cloudflare Worker (Control Plane и Tier 1 Data Plane)
│   ├── src/
│   │   ├── adapters/       # Хранилище нонсов на Durable Objects, KV кэш банов, сессии
│   │   ├── domain/         # Сервис challenge-response, VLESS парсер, политика банов
│   │   └── handlers/       # Эндпоинты: /nonce, /auth, /enroll, /proxy, /xhttp
│   └── wrangler.toml       # Конфигурация воркера и биндингов Cloudflare
├── control-plane-admin/    # Origin API, монитор и портал выдачи (Python 3.12 / FastAPI)
│   ├── another_admin/
│   │   ├── adapters/       # Асинхронный Mongo store, шифрование keyfile, интеграция с CI
│   │   ├── api/            # Подписанные команды админки, внутренний прокси воркера, веб-портал
│   │   └── domain/         # Детектор аномалий, сборщик клиентских инсталляторов
│   └── scripts/            # Скрипт сборки инсталлятора для GitHub Actions
├── app/                    # Мультиплатформенный клиент (Flutter и нативный Android VpnService)
├── infra/                  # Инфраструктура как код (Terraform)
│   ├── cloudflare/         # Развертывание Worker, KV и DNS записей
│   └── generic-vps/        # Cloud-init и Compose для VPS-нод выхода
└── deploy/origin/          # Dockerfile и docker-compose для развертывания Origin-стека
```

## Модель безопасности и криптографии

```text
                     [ Оператор / Админ ]
                              │
               Зашифрованный файл ключа (.another-admin-key)
               Двойная подпись: Ed25519 + ML-DSA-65 (FIPS 204)
               Инкрементный счетчик + Хэш-цепочка
                              ▼
      ┌──────────────────────────────────────────────┐
      │  Control Plane API (FastAPI / PyMongo Async) │
      └──────────────────────┬───────────────────────┘
                             │
            Внутренний REST-прокси (Service Secret)
                             ▼
      ┌──────────────────────────────────────────────┐
      │   Cloudflare Edge Worker (Tier 1 Шлюз)       │
      └──────────────────────▲───────────────────────┘
                             │
     1. GET /nonce           │ 3. Подпись: Ed25519(nonce || ts)
     2. Выдача нонса (DO)    │ 4. POST /auth -> Сессионный билет + VLESS UUID
                             │
                     [ Устройство клиента ]
               Приватный ключ (Никогда не экспортируется)
             Userspace L3 NAT -> VLESS WebSocket / Reality
```

1. **Защита от Replay-атак**: Выдача и погашение одноразовых нонсов на Edge осуществляется через **Cloudflare Durable Object** (`NonceLedgerObject`), гарантирующий строгую консистентность между всеми дата-центрами Cloudflare.
2. **Идентичность клиента**: Генерируется на стороне устройства. Публичные ключи привязываются к профилю по хэшу одноразового инвайт-токена в базе MongoDB.
3. **Сессионные токены**: При успешном прохождении challenge-response клиент получает короткоживущий токен и уникальный VLESS UUID для авторизации внутри туннеля данных.

## Тестирование

Все подсистемы изолированы интерфейсами и покрыты автоматическими тестами:

```bash
# Go Core: тесты NAT-движка, TCP/IP парсера, Reality, WebSocket и криптографии
cd core && go test -v -race ./...

# Edge Worker: тесты логики авторизации, проверки подписей и протокола VLESS
cd edge && npm test

# Control Plane: тесты цепочки подписей команд, детектора аномалий и API
cd control-plane-admin && pytest
```
