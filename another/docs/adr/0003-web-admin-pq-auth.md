# ADR 0003: Web-админка и отдельный backend API

## Статус
Принято (аудит 2026-08-25).

## Контекст
v1 админки — Telegram-бот (aiogram) + CLI. Оператор явно запретил сторонние
сервисы как канал управления и хочет пускать в админку нескольких людей.
Нужен монитор, не только «команды бота».

Desktop держал бы поверхность атаки меньше, но недоступен с другой машины
и с телефона. Web — да.

Прямой `pymongo` из браузера невозможен; прямой `pymongo` из SPA-сервера
на каждый экран потом придётся дублировать для сайта автовыдачи сборок.

## Решение
- Админка — Web, хостинг: статика на Vercel и/или тот же origin HF.
- Backend API на HF (резерв — тот же образ на Render), PyMongo Async.
- Аутентификация — Another Auth v1 ([auth-spec.md](../auth-spec.md)), не
  email/password и не Telegram user id.
- Telegram-бот не развивается и не входит в релиз. CLI остаётся для keygen
  и аварии.
- Worker для админ-команд — слепой прокси (E2E к origin), см. auth-spec §3.

## Последствия
- Нужна модель угроз «браузер»: ключ не в localStorage.
- Нужен дизайн и вёрстки оператора — но UI после стабильного API.
- `admin-bot-deploy.yml` со временем удалить или заморозить.
