# ADR 0008: Hugging Face Space как основной compute-узел

## Статус
Принято оператором (аудит 2026-08-25). Отменяет рекомендацию architecture.md
v2.0 «не использовать HF как штатный узел».

## Контекст
Content Policy HF запрещает прокси для обхода ограничений. Ban аккаунтов
за такое — не гипотеза. В ревизии спеки HF понизили до experimental.

У оператора CPU Basic Space: Docker, 16 ГБ RAM, бесплатно (legacy), самый
мощный узел инвентаря. Render — 0.1 CPU. VPS нет.

## Решение
HF Space — **основной origin**: data-plane, mongo REST-прокси, admin API.
Риск бана принят. Снаружи из РФ Space по возможности не светить: вход —
Cloudflare Worker. Один Docker-образ с Render (Render = холодный резерв +
пингер).

Эфемерные 50 ГБ после старта не использовать как единственное хранилище
логов/артефактов.

## Последствия
Аккаунт HF — единая точка отказа по ToS. Держать Render-клон и возможность
переехать API на любой Docker. Не класть в Space единственную копию секретов
без бэкапа у оператора.
