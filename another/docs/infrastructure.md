# Доступная инфраструктура

Этот документ описывает **то, что у оператора есть сейчас**, а не «любой VPS
за $5». Архитектура должна складываться из этого набора. Все узлы можно и
нужно использовать **одновременно**.

Никаких деплоев из этого документа не следует — только карта и правила
сложения. Когда появится новый провайдер, его вписывают как ещё один модуль
Terraform + ещё один вход в сетку, а не как переписывание системы.

## Инвентарь

| Узел | Что это по факту | Лимиты / поведение | Роль в Another |
|---|---|---|---|
| **Hugging Face Space (CPU Basic)** | Полноценный Docker. Для оператора бесплатно (legacy). 16 ГБ RAM, 1 ГБ в репозитории образа, после старта можно докачать до **50 ГБ эфемерного** диска (сгорает при рестарте). По тарифу должен засыпать раз в 48 ч; у этого инстанса сон не наблюдается, на это **нельзя опираться**. | ToS HF формально запрещает прокси для обхода ограничений исходного сервиса. Риск бана аккаунта **принят осознанно**: это самый мощный узел из имеющихся. | **Основной compute:** data-plane прокси, Mongo REST-прокси, admin API, компактные логи в Mongo (не на эфемерный диск), позже — сборка инсталляторов. Снаружи по возможности только через Cloudflare Worker. |
| **Cloudflare Worker** | Serverless на edge, TCP `connect()`, Durable Objects, KV, Cron. | Нет сырого TLS ClientHello → **Reality здесь не живёт**. Нет Mongo-драйвера по TCP. Data API Atlas **мёртв** (EOL 2025-09-30). | **Универсальный вход** (часто в вайтлистах РФ), пингер, reverse-proxy на HF/Render/Vercel, `/nonce` `/auth` `/enroll`, лёгкий VLESS-WS шлюз. Blind-relay для админ-API (не читать тело команд). |
| **MongoDB Atlas** | Облачная БД, подключение по `MONGO_URI` (драйвер). | M0: 512 МБ, один кластер на проект Atlas. Data API / App Services — **выключены**. | Источник истины: пользователи, ключи, баны, квоты, chain-head админов, capped-коллекция логов. |
| **Render (free)** | Docker-контейнер, засыпает ~15 мин. ~0.1 CPU, RAM неизвестна (мало). Сомнения по доступности из РФ без VPN. | Холодный старт 30–60 с. Пингер с Worker это снимает, мощность — нет. | **Резервная копия того же образа, что и HF.** Не основной compute. |
| **Vercel (free serverless)** | Засыпающий serverless + статика. | Не TCP-прокси. Таймауты функций. | Статика админки и/или лёгкий health/config endpoint. Не data-plane. |
| **GitHub repo CDN** | Раздача файлов репозитория / релизов. | Публичность = обнаруживаемость проекта. Для закрытого круга — **приватный** репозиторий или одноразовые артефакты не через публичный URL. | Позже: раздача инсталляторов по одноразовой ссылке (не сейчас). |
| **Cloudinary CDN** | Раздача медиа. | Тот же риск засветки, плюс ToS. | Запасной канал раздачи артефактов, не трафик VPN. |
| **VPS (Tier 2)** | Пока **нет**. | Reality требует стабильный IP и контроль TLS. | Обязателен по замыслу релиза. Terraform-модуль готовится заранее, провайдер — когда появится. |

`MONGO_URI` — единственный живой способ говорить с Atlas. Worker ходит в Mongo
**только** через наш REST-прокси (на HF, дубль на Render). См.
[ADR 0005](adr/0005-mongo-rest-proxy.md).

## Чего нет и не надо притворяться, что есть

- Нет выделенного VPS → нет Reality «прямо сейчас». Протокол обязателен к
  реализации в клиенте и серверном образе, но включится, когда появится IP.
- Нет объектного хранилища с гарантией (R2 / S3). Логи **нельзя** складывать
  на эфемерный диск HF (50 ГБ сгорят при рестарте Space). Логи — в Mongo
  capped collection. См. [observability.md](observability.md).
- Нет стриминга, на который можно опереться (долгие WS через весь стек
  HF/Render/Vercel ненадежны). Админка **поллит** (квота — порядка минуты,
  алерты/сессии — чаще).
- `motor` (async Mongo для Python) deprecated с 2025-05-14, sunset 2026-05-14.
  Новый Python-код — **PyMongo Async API**, не motor.

## Сетка входов: «дотянулся до одного — работает всё»

Клиент хранит список entrypoints (зашит в сборку приглашения). Порядок не
фиксированный: при подключении **пробник** меряет, какие входы отвечают и с
каким RTT, затем выбирает путь.

```
[Клиент в РФ]
    │
    ├─① Cloudflare Worker (часто вайтлист) ──proxy──► HF Space (основной)
    │                                              └─proxy──► Render (если HF лёг)
    ├─② прямой HF Space (если huggingface.co не заблокирован)
    ├─③ прямой Render (если onrender.com доступен)
    └─④ позже: VPS Reality / xHTTP (когда появится IP)
```

Правила:

1. Узлы умеют проксировать **друг друга**. Worker → HF, Worker → Render,
   HF → Render, Render → HF. Клиенту достаточно одного живого входа.
2. Лишний хоп — это задержка. Если прямой путь до HF/Render живой и быстрее
   пути через Worker — берём прямой. Worker — не идеология, а запасной вход
   под вайтлист и блокировку origin-доменов.
3. На вайтлисте провайдера (проходят только разрешённые IP) прямой HF/Render/VPS
   почти наверняка мёртв. Тогда **единственный** рабочий вход — тот, чей IP
   в списке (на практике часто диапазоны Cloudflare). Весь трафик:
   клиент → Worker → наш origin. Это нормально и ожидаемо, не «баг failover».
4. Пингер — Cloudflare Cron. Список URL для пинга **редактируется в админке**
   без передеплоя Worker (KV или Mongo через прокси). Не хардкодить только
   Render.
5. Один и тот же Docker-образ для HF и Render, чтобы резерв не разъезжался
   с основным.

Terraform сегодня закрывает только Cloudflare (`infra/cloudflare/`). Дальше —
модули под Render/HF (насколько позволяют API) и **generic VPS** (cloud-init +
docker compose), чтобы нового провайдера добавлять runbook'ом, а не с нуля.

## Доступность из РФ

| Вход | Ожидание |
|---|---|
| Cloudflare | Часто жив даже на мобильных вайтлистах (диапазоны CF бывают в WL). Не гарантия: CF тоже режут точечно. |
| huggingface.co | Может быть в РКН / ТСПУ. Не полагаться как на прямой вход из РФ. |
| onrender.com | Сомнителен из РФ без VPN. Резерв скорее для клиента, который уже «снаружи», или как origin за Worker. |
| vercel.app | То же. Статика админки с операторской машины (часто не из-под домашнего ТСПУ) — ок. |
| Будущий VPS | На вайтлисте бесполезен, пока IP не из WL. Для обычного ТСПУ — как раз Reality/xHTTP. |

Админка — Web, рассчитана на то, что ей пользуются **не только** из-под того же
ТСПУ, что и клиенты (оператор, возможно несколько людей). Если админ сидит в РФ
на вайтлисте — админка тоже должна открываться через CF-вход (тот же Worker как
HTTPS-фронт).

## Секреты и gitignore

В git не попадают: `.env`, ключи (`*.pem` `*.key` `*.seed`), tfstate, сборки
инсталляторов, `docs/private/`. Строка `MONGO_URI` — только в секрет-хранилище
узла (HF secrets, Render env, Cloudflare Secrets), не в репозитории.

`docs/private/` — для локальных заметок оператора (реальные URL, account id),
которые не нужны агенту в общем виде и не должны уехать вместе с git-копией.
