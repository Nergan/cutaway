# Принципы проекта Another

## Имя

**Another** = «ещё один (VPN)» / «другой (VPN)». Не бренд, не продукт для
витрины. Имя намеренно пресное: проект не должен светиться как «VPN для обхода».

## Для кого

Закрытый круг людей, которым оператор лично выдал доступ. Публичный релиз,
магазин приложений, лендинг «скачать VPN» — **не цели**. Критерий «готово к
релизу» задаёт оператор (когда устанет наращивать систему), а не календарь.

## Два главных принципа

1. **Кроссплатформенность.** Один и тот же клиент должен жить на максимальном
   числе платформ, на которых реально удержать современный сетевой стек.
   Приоритет релиза: Windows 10/11, Linux (как можно больше дистрибутивов),
   Android. Windows 7/8 — отдельный best-effort контур. macOS и iOS — вне
   скоупа релиза. Windows XP — практически недостижим, не обещать.
   Подробности и честная матрица — [ADR 0007](adr/0007-platform-scope.md).

2. **Скорость.** Обход блокировок, который «работает, но с 800 мс и 2 Мбит/с»,
   для закрытого круга всё равно плохой VPN. Failover, выбор входа и цепочка
   прокси должны оптимизироваться по RTT и пропускной способности, а не только
   по «подключился хоть куда-нибудь». См. [infrastructure.md](infrastructure.md)
   § «Сетка входов».

Оба принципа важнее удобства разработки, единообразия UI-фреймворка и
привычки «сначала нарисовать экран». Сначала протоколы, идентичность, TUN,
узлы; GUI — после того, как логика держится.

## Модель доступа

Пользоваться системой могут **только те, кому оператор дал доступ**.
Инсталлятор без одноразового приглашения бесполезен. Приглашение сгорает
после первого успешного enroll. Поделиться уже активированным профилем —
это компрометация ключа, лечится ревокацией в админке, не «криптостойкостью
бинарника».

Подробности: [provisioning.md](provisioning.md).

## Что система обещает и чего нет

**Обещает:**

- Перехват трафика устройства (TUN) и kill switch, не «ручной системный прокси».
- Устойчивость к DPI в первую очередь в РФ (ТСПУ), насколько позволяет
  доступная инфраструктура и смена транспортов.
- Админка как монитор состояния + инструмент бана/выдачи доступа, без
  сторонних мессенджеров.
- Постквантовая гибридная идентичность (Ed25519 + ML-DSA-65) у клиента и
  у админа.

**Не обещает:**

- Анонимность от оператора инфраструктуры (Cloudflare / HF / Mongo / Render
  видят метаданные). Это DPI-VPN, не Tor.
- Работу при полном отключении интернета. Нет пути — нет туннеля.
- Неуязвимость бинарника к реверсу. Постквантовая подпись не прячет ключ в
  exe. См. [provisioning.md](provisioning.md) и [auth-spec.md](auth-spec.md).
- Вечную работу одного протокола. ТСПУ и GFW — это гонка. Клиент должен уметь
  менять транспорт, не ждать новый «серебряный» протокол.

## Как работаем над кодом

- Верифицировать реальными инструментами там, где они есть. Где нет (Flutter
  SDK, Terraform registry, Xcode) — в документации пишется TODO: что сделать
  оператору, как прогнать, какую обратную связь ждать. Не выдавать непрогнанное
  за проверенное.
- Сначала логика и протоколы, потом UI. Прогон Flutter-GUI — не первый шаг.
- Не деплоить, пока оператор явно не попросил.
- Лицензии референсов: анализировать `xray-core` / `sing-box` можно,
  копировать нельзя ([ADR 0002](adr/0002-vless-reimplementation.md)).
