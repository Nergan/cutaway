# Целевая архитектура

Как устроить formular, чтобы он стал any-to-any конвертером при ограничениях из `02-constraints.md`. Конкретные операции — в `07-catalog.md`, AI — в `04-ai.md`, API — в `05-api.md`, интерфейс — в `06-ux.md`.

## 1. Принципы

1. **Один реестр операций — источник правды** для интерфейса, планировщика, API и MCP. Никаких параллельных таблиц вроде нынешних `ALLOWED_CONVERSIONS` и `DIRECT_EDGES`.
2. **Сначала браузер.** Шаг выполняется на сервере, только если браузер не может его выполнить, если результат должен пережить закрытие вкладки или если шаг вызван через API. Браузер — главный источник «безлимитности»: железо пользователя, никакой нагрузки на общий Space, файл не покидает устройство.
3. **Каждый результат — новый ассет** в том же рабочем пространстве. Цепочки получаются естественно: результат можно обрабатывать дальше.
4. **Сначала выбор, потом действие.** Набор доступных действий вычисляется по типам и количеству выбранных ассетов.
5. **Честность.** Перед запуском пользователь видит путь, место выполнения, оценку времени, потери качества и использование AI.
6. **Короткая жизнь данных.** Рабочее пространство живёт не дольше 24 часов (решение D4). Ничего не хранится дольше, чем нужно.
7. **Ничего пользовательского не исполняется.** Загруженные файлы только читаются конвертерами с лимитами по времени, памяти и размеру.

## 2. Модель данных

### Вид и формат
- **Вид (kind)** — смысловой тип: `document`, `spreadsheet`, `data` (структурированные данные), `image`, `vector`, `audio`, `video`, `subtitles`, `font`, `archive` (коллекция), `model3d`, `geo`, `notation`, `diagram`, `text`, `code`, `binary`, `email`, `calendar`, `contacts`.
- **Формат (format)** — описание сериализации: `id` (`mp4`), `kind`, MIME-типы, расширения, правила детекции, кодеки чтения/записи по исполнителям. Форматы, которые формально и вид, и коллекция (многостраничный PDF, анимированный GIF, архив), помечаются флагом `collection_of`.

### Ассет
Поля:
- `id`, `workspace_id`, `name`, `size`, `sha256`;
- `format` — с уверенностью детекции и альтернативами; пользователь может переопределить;
- `origin` — `upload`, `job` (с `job_id` и шагом) или `browser` (результат браузерного шага, загруженный пользователем);
- `lineage` — список родительских ассетов и операция;
- `storage` — локальный путь байтов. Внешнего зеркала нет (решение D13);
- `encryption` — не используется, пока нет зеркала; ключ по D12 жил бы только в ссылке;
- `preview` — миниатюра, длительность, размеры, число страниц;
- `ai` — использовался ли AI, какие модели;
- `created_at`, `expires_at`.

### Операция
Каждая операция описывается декларативно и регистрируется в реестре:
- `id` (`convert`, `video.replace_audio`, `pdf.merge`, `audio.transcribe`) и `version`;
- `title`, `description` (ru/en), `category`: `convert`, `edit`, `extract`, `compose`, `generate`, `analyze`, `query`;
- `inputs` — роли: `name`, допустимые виды/форматы, `min`/`max` (для N-арных операций), подсказка UI; например, у `video.replace_audio` роли `video` (1) и `audio` (1);
- `outputs` — виды/форматы результата (могут зависеть от параметров);
- `params` — JSON Schema плюс подсказки UI: какой редактор параметра показать (таймлайн обрезки, кроп, слайдер, выбор модели);
- `executors` — список реализаций: `browser` или `server`, движок, требования (WebGPU, crossOriginIsolated, Java), максимальный размер входа, модель стоимости (время на МБ или на секунду медиа, пик памяти);
- `loss` — `lossless`, `lossy` или `structural` (теряется структура или форматирование) с пояснением;
- `ai` — `null` или описание: задача, политика подбора модели, требования к ресурсам;
- `license_notes` — атрибуция, если нужна (например, для моделей CC-BY).

Конвертация «формат A → формат B» — частный случай операции `convert`, которую реестр генерирует из кодеков форматов. Вручную описываются только прямые переходы движков: какой движок читает A и пишет B.

### Рецепт
Рецепт — направленный ациклический граф шагов:

```json
{
  "steps": [
    {"id": "a", "op": "audio.normalize", "inputs": {"audio": "asset:7f3c"}, "params": {"target_lufs": -16}},
    {"id": "b", "op": "video.replace_audio", "inputs": {"video": "asset:91aa", "audio": "step:a"}, "params": {"shortest": true}},
    {"id": "c", "op": "convert", "inputs": {"source": "step:b"}, "params": {"to": "webm"}}
  ]
}
```

Тот же JSON используется в API, сохраняется как пользовательский рецепт и применяется к другим файлам: ссылки `asset:` заменяются на новые ассеты с совместимыми ролями.

## 3. Планировщик

### Что можно сделать с выделением
- **Один ассет:** форматы, достижимые через граф кодеков за разумное число шагов, плюс операции, у которых есть роль, принимающая этот вид.
- **Несколько ассетов:**
  - операции, роли которых можно заполнить выделенными ассетами (сопоставление ролей и видов; при неоднозначности — спросить, кто есть кто);
  - пакетные версии одноассетных операций (применить ко всем подходящим, остальные — «пропущено»);
  - N-арные операции: склейка, объединение, архив, коллаж.
- **Перетаскивание A на B:** операции с двумя ролями, где A подходит под одну роль, а B — под другую.

### Поиск пути
- Взвешенный поиск кратчайшего пути (Дейкстра или A*) по графу «формат + ограничения». Стоимость ребра:
  `w_time · время + w_loss · потери + w_ai · штраф_AI + w_size · рост_размера + штраф_исполнителя`.
- Исполнитель учитывается контекстом: доступен ли WebGPU, есть ли cross-origin isolation, свободен ли сервер, вызов из API (тогда только сервер).
- Пользователю показываются до трёх вариантов: «оптимально», «быстрее», «качественнее», если они различаются.
- AI-рёбра по умолчанию имеют высокий штраф: AI в путь попадает только если без него цель недостижима или пользователь явно выбрал AI-операцию. Такой путь помечается.

### Коллекции
Если операция принимает вид X, а ассет — коллекция элементов X (архив картинок, PDF как набор страниц, кадры видео), операция «поднимается»: применяется к каждому элементу, результаты собираются в коллекцию того же вида (архив, PDF) или в отдельные ассеты — по выбору пользователя. Распаковка архива прямо в рабочее пространство — тоже операция.

### Проверки перед запуском
Схема параметров, лимиты размера для выбранного исполнителя, доступность ресурсов (память под модель, место на диске), лицензионная политика для AI-шагов, квоты пользователя.

## 4. Исполнители

### Браузерный
- Шаги выполняются в Web Workers, чтобы не блокировать интерфейс.
- Стек и ограничения — в `04-ai.md` (AI) и `07-catalog.md` (движки). Основное: Mediabunny + WebCodecs для медиа, ffmpeg.wasm как запасной вариант, jSquash / magick-wasm / libheif-js для изображений, pdf.js и форк pdf-lib для PDF, SheetJS / DuckDB-WASM для таблиц, pandoc.wasm для документов, libarchive.js / fflate для архивов, three.js + assimpjs для 3D, Transformers.js для AI.
- Результаты живут в памяти и OPFS. По желанию пользователя (или если следующий шаг серверный) результат загружается в рабочее пространство.
- Выбор исполнителя — по проверке возможностей (`crossOriginIsolated`, `navigator.gpu`, `VideoEncoder.isConfigSupported`, `navigator.deviceMemory`), а не по User-Agent.
- Ограничение: при закрытии вкладки браузерный шаг прерывается. Интерфейс это явно показывает.

### Серверный
- Исполнитель задач внутри процесса formular: asyncio-цикл, который берёт задачи из очереди и запускает движки через `shared_runtime.run_process` (отдельная группа процессов, таймауты, ограничение вывода).
- Одновременно выполняется не больше `FORMULAR_MAX_CONCURRENT_JOBS` тяжёлых задач (на HF — 1). Короткие HTTP-запросы при этом обслуживаются параллельно.
- Тяжёлые подпроцессы запускаются с низким приоритетом и ограничением числа потоков (`08-infrastructure.md`).
- Адаптеры движков: LibreOffice, pandoc, ffmpeg, 7-Zip, Pillow/libvips, CairoSVG/resvg, DuckDB и т. д. AI-адаптеры — в `04-ai.md`.

### Смешанные цепочки
Цепочка может начинаться в браузере и продолжаться на сервере. Например, обрезка большого видео в браузере без перекодирования, затем загрузка уже маленького фрагмента и распознавание речи на сервере. Планировщик старается выполнять первыми шаги, которые сильнее всего уменьшают объём данных.

## 5. Задачи и очередь (MongoDB)

### Коллекции
База `formular` в общем кластере:
- `workspaces` — id, даты, `expires_at` (TTL-индекс), квоты, счётчики;
- `assets` — метаданные ассетов (без байтов), TTL-индекс;
- `jobs` — задачи, TTL-индекс;
- `models` — реестр моделей для AI (`04-ai.md`);
- `api_keys` — при необходимости (`05-api.md`).

Документы маленькие. Логи задачи — не больше нескольких КБ (хвост).

### Жизненный цикл задачи
Состояния: `queued → running → succeeded | failed | canceled`, а также `interrupted` (сервер перезапустился во время выполнения), `awaiting_key` (после рестарта задаче нужен ключ из ссылки, чтобы расшифровать зеркало; она ждёт, пока пользователь снова откроет ссылку) и `expired`.

- **Захват:** `find_one_and_update({status: "queued"}, {$set: {status: "running", lease_owner, lease_expires_at}})` с сортировкой по приоритету и времени создания.
- **Heartbeat:** раз в 15–30 секунд продлевать аренду (срок около 2 минут) условным обновлением «только если владелец аренды — всё ещё я». Если продлить не удалось, аренда потеряна: процесс движка убивается, задачу доделает новый владелец. Задача без продления считается брошенной.
- **Восстановление:** при старте worker переводит `running` с истёкшей арендой в `queued` с `attempts + 1`. После 2–3 попыток задача становится `failed` с понятной причиной. Если входные файлы пропали вместе с диском (не было зеркала), задача становится `interrupted` с просьбой загрузить файл снова.
- **Контрольные точки:** каждый шаг рецепта атомарен, промежуточные результаты сохраняются как ассеты. Перезапуск продолжает с первого незавершённого шага. Длинные шаги, которые можно резать (распознавание речи по сегментам, перевод по абзацам), сохраняют частичный результат.
- **Отмена:** флаг `cancel_requested`; исполнитель проверяет его и убивает группу процессов.
- **Прогресс:** хранится в памяти и отдаётся опросом. В Mongo пишется не чаще раза в несколько секунд — лимит M0 100 операций в секунду общий на всю экосистему.
- **Справедливость:**
  - очередь по кругу между рабочими пространствами;
  - не больше одной выполняемой задачи на рабочее пространство — это гарантирует частичный уникальный индекс по `workspace_id` для статуса `running`;
  - короткие задачи (по оценке) вперёд длинных;
  - лимиты на число задач и суммарное время на рабочее пространство и IP.
- **Идемпотентность:** клиент передаёт ключ задачи, повторная отправка не создаёт дубль.
- **Без Mongo** (локальная разработка, сбой кластера): очередь в памяти; при рестарте задачи теряются, интерфейс об этом сообщает.

### Почему не готовая библиотека очередей
arq требует Redis, saq — Redis или Postgres, Procrastinate — Postgres; в Celery 5.6 брокера MongoDB больше нет; Huey с SQLite потеряет базу вместе с эфемерным диском. Бесплатного Upstash Redis (500 тысяч команд в месяц) не хватит даже на холостой опрос одним worker. Очередь на арендах в Mongo — около 200 строк кода, без новой инфраструктуры. Готовый вариант для оценки — `mongo-taskqueue` (аренды, heartbeat, повторы, дедупликация, приоритеты).

## 6. Хранение файлов

С учётом D4 (не больше суток) долговременное хранилище не нужно.

1. **Локальный диск — основной носитель.** Файлы лежат в каталоге рабочего пространства внутри runtime-каталога formular. Диск стирается при рестарте и учитывается в `temp_mb`, поэтому formular сам следит за своими бюджетами: общий объём файлов задач, объём на рабочее пространство, свободное место. При нехватке новые задачи ждут или отклоняются с объяснением.
2. **Зеркала в Cloudinary нет (решение D13).** Formular не пишет в общий аккаунт и не тратит его кредиты. Файлы живут только в каталоге рабочего пространства на локальном диске, от 12 часов и не дольше 24. Если процесс перезапустился, пользователь видит «Сервер перезапускался, файл нужно загрузить заново», а метаданные из Mongo объясняют, что именно потеряно.
3. **HF Storage Buckets — возможное улучшение, не для первой версии.**
   - Квота бесплатного аккаунта (100 ГБ приватного хранения, общая с репозиториями) распространяется и на бакеты; трафик не тарифицируется.
   - Доступ — через S3 API (`https://s3.hf.co/<namespace>`, boto3). Правил автоудаления нет — чистить самим.
   - Подписанные GET-ссылки подтверждены только сторонним тестом; подписанные PUT и CORS для загрузки из браузера не проверены.
   - Бакет **не монтировать** в Space как том: это изменение настроек legacy-Space с неизвестными последствиями (`02-constraints.md`, раздел 1). Только S3 API.
   - Dataset-репозитории как временное хранилище не подходят: удалённые файлы продолжают занимать квоту, у коммита таймаут 60 секунд.

   Сторонние S3-хранилища рассмотрены и отклонены. Хранилище CDN-провайдера из правила `tunnel_worker` требует банковскую карту и рискованно из-за сканера HF; остальные бесплатные тарифы либо малы, либо засыпают, либо запрещают такое использование условиями.

Очистка: фоновая задача раз в несколько минут удаляет истёкшие рабочие пространства с диска; TTL-индексы чистят метаданные в Mongo. Отдельного внешнего зеркала нет, чистить его не нужно.

## 7. Ссылки и шифрование

- Ссылка на рабочее пространство: `/formular/w/<workspace_id>#k=<key>`.
  - `workspace_id` — не меньше 128 случайных бит в base64url.
  - `key` — 256 случайных бит, генерируется в браузере.
- Часть после `#` браузер не отправляет на сервер. Ключ уходит на сервер только явно, в заголовке запроса, когда серверу нужно прочитать зашифрованное зеркало или записать в него. На сервере ключ живёт в памяти на время задачи и нигде не сохраняется.
- Модель угроз: шифрование защищает зеркало у стороннего провайдера и любые долговременные копии. Сам сервер видит открытые данные во время обработки — без этого конвертация невозможна. На локальном диске контейнера файлы лежат открыто, а диск эфемерный.
- Ссылка без фрагмента открывает метаданные, но зеркальные файлы не расшифровываются — интерфейс это объясняет.
- История рабочих пространств хранится в `localStorage` на устройстве пользователя (id, ключ, срок); есть кнопка «забыть».
- Потерянная ссылка означает потерянные данные. Интерфейс говорит об этом при создании ссылки.
- Для API шифрование зеркала опционально: если клиент не передал ключ, зеркало не используется.
- Гигиена неугадываемых ссылок (рекомендации W3C TAG):
  - в Mongo хранится только SHA-256 от `workspace_id`, а не сам идентификатор — утечка базы не раскрывает ссылки;
  - `Referrer-Policy: no-referrer`, `X-Robots-Tag: noindex` и запрет `/formular/w/` в robots;
  - лимит на перебор идентификаторов;
  - после истечения срока — ответ 410.
- **На страницах рабочего пространства — никаких сторонних скриптов.** Любой скрипт страницы видит `location.hash`, то есть ключ.
  - Библиотеки раздавать с собственного origin или закреплять версии с SRI. Сейчас SortableJS грузится как `@latest`, а виджет доната — со стороннего CDN.
  - После чтения ключа убирать фрагмент из адресной строки (`history.replaceState`); ключ остаётся в локальной истории.
- **Где держать ключ (решение D12):** только во фрагменте ссылки. Серверного мастер-ключа нет. Пока зеркала нет (D13), ключ не используется; если зеркало когда-нибудь появится, сервер не сможет прочитать его без ключа пользователя, и после рестарта задача будет ждать ключ.

## 8. Доставка прогресса

- Основной способ — опрос `GET` состояния рабочего пространства или задачи раз в 1–3 секунды, адаптивно, с `ETag` и ответом 304. Запросы короткие и совместимы с ограничением параллелизма оркестратора.
- SSE — только после увеличения `max_concurrency`. Соединение обрывается через `request_timeout_seconds` = 600 с, клиент должен переподключаться.
- Когда вкладка скрыта, опрос замедляется; когда задача завершилась — уведомление (`06-ux.md`).

## 9. Кэширование и экономия

- Повторное использование результата внутри рабочего пространства: ключ — `sha256(вход) + id операции + нормализованные параметры + версия движка` (для AI — плюс модель и её ревизия).
- Между рабочими пространствами результаты не переиспользуются: это утечка информации о чужих файлах.
- Везде, где можно, копирование потоков без перекодирования: смена контейнера, обрезка по ключевым кадрам, замена аудиодорожки с `-c:v copy`.
- Превью генерируются в браузере; сервер делает их только для форматов, которые браузер не читает.

## 10. Безопасность

- Все загрузки недоверенные:
  - лимиты по времени, памяти и размеру файла (rlimit оркестратора плюс таймауты движков);
  - проверка архивов на «бомбы» и выход за каталог (уже есть, сохранить);

- **Общий origin экосистемы — критично.** Все проекты работают на одном origin (`nargan-projects.hf.space`), а `localStorage`, IndexedDB и cookies разделяются по origin, а не по пути. Пользовательский HTML или SVG, открытый inline с этого origin, выполнит скрипт с доступом к данным всех проектов — например, к ключам личности netlazy в IndexedDB. Поэтому:
  - файлы отдаются только с `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff` и неисполняемым `Content-Type` (сейчас `/api/convert` так и делает — сохранить);
  - превью HTML, SVG и документов — только в `iframe` с атрибутом `sandbox` без `allow-same-origin`, из blob-URL, или как картинка и текст;
  - пользовательский контент никогда не отдаётся inline с origin приложения.

  Обратная сторона того же: ключи рабочих пространств в `localStorage` видны скриптам любого проекта экосистемы. Это известное ограничение общего origin; XSS в любом соседнем проекте раскрывает ключи formular.
