# AI в formular

С учётом решений D2 (только свои бесплатные ресурсы) и D3 (только пермиссивные лицензии). Цифры производительности для 2 vCPU в основном экстраполированы из замеров на более мощных процессорах — перед реализацией мерить на Space.

## 1. Где выполняется AI

- **Сервер (CPU Space):** 2 vCPU, общие с хабом и соседями, и не больше 5–6 ГБ памяти после изменений из `08-infrastructure.md`. Годится для распознавания и анализа: речь, OCR, документы, перевод, лёгкие модели обработки изображений.
- **Браузер пользователя:** Transformers.js v4 (ONNX Runtime Web, WebGPU с откатом на WASM), sherpa-onnx WASM, при необходимости WebLLM. Модели браузер скачивает напрямую с CDN Hugging Face, сервер не нагружается. Это единственный «GPU», доступный бесплатно, и он подходит под D2: вход через HF и оплата не нужны.
- **Не используются:** Inference Providers, ZeroGPU, вход через HF (решение D2).

## 2. Что реально из запрошенного

| Запрос | Статус | Где | Комментарий |
|---|---|---|---|
| Изображение → текст (подписи, OCR, документ → Markdown) | реально | сервер и браузер | Tesseract, RapidOCR, Florence-2, Docling |
| Аудио/видео → текст (транскрипт, субтитры, говорящие) | реально | сервер и браузер | GigaAM-v3 для русского, Parakeet v3, Whisper |
| Текст → речь | реально, мало голосов | сервер и браузер | Пермиссивных русских голосов немного: голоса Piper с подходящими лицензиями через sherpa-onnx, Silero `v5_cis_base` |
| Перевод документов с сохранением стиля и структуры | реально | сервер (MT), браузер (MT) | Свой пайплайн по разметке документа (раздел 8); качество MT среднее, LLM на CPU медленные |
| Декомпиляция | байткод — реально, нативный код — частично | сервер | Раздел 9 |
| Текст → изображение | эксперимент | сервер, возможно браузер | Пермиссивных небольших моделей мало; минуты на картинку или недоступно — решает автоподбор |
| Текст → 3D | эксперимент | сервер | Картинка → 3D через TripoSR (MIT, минуты) или LLM пишет код CAD-модели |
| Текст → звук/музыка | генеративно нереально | — | Пермиссивных моделей в нашем бюджете нет; только процедурно: LLM или правила пишут ноты (ABC/MIDI), FluidSynth рендерит |
| Текст → видео | генеративно нереально | — | Только процедурно: сценарий → озвучка → слайды → ffmpeg (панорамирование и масштаб, субтитры). Это честно помеченный AI-пайплайн, но не генеративное видео |

## 3. Каталог моделей по задачам

Это стартовые кандидаты для автоподбора, а не захардкоженный выбор (решение D6). Лицензии перепроверять при реализации.

  - GigaAM-v3 (MIT; лучший для русского; ONNX);
  - NVIDIA Parakeet-TDT-0.6B-v3 (CC-BY-4.0; 25 языков, включая русский; ONNX/sherpa-onnx; RTF около 0.03 на 4 ядрах);
  - Whisper через faster-whisper/CTranslate2 int8 (MIT; многоязычный);
  - Qwen3-ASR 0.6B (Apache-2.0; медленнее).

  Moonshine годится только для английского: модели для других языков некоммерческие.
- **Метки времени по словам:** Qwen3-ForcedAligner-0.6B (Apache-2.0; 11 языков, включая русский). У WhisperX лицензия моделей выравнивания зависит от языка — проверять.
- **Говорящие (диаризация):** модели sherpa-onnx (проверить лицензии конкретных моделей). pyannote community-1 требует принять условия на HF (gated) — исключить.
- **Озвучка:**
  - голоса Piper — запускать через sherpa-onnx (Apache-2.0), а не через сам Piper (движок с версии 1.3 под GPL-3.0); лицензия у каждого голоса своя;
  - Silero `v5_cis_base` (MIT);
  - для английского — Kokoro-82M (Apache-2.0) и Kitten TTS (Apache-2.0).

  Клонирование голоса не делаем.
- **OCR и документы:**
  - Tesseract 5 (Apache-2.0; rus, eng);
  - RapidOCR + PP-OCRv5 (Apache-2.0; модель eslav для кириллицы);
  - Florence-2 base/large (MIT; подписи, OCR, детекция);
  - Docling (MIT; документ → Markdown/JSON; проверить лицензию моделей вёрстки);
  - SmolVLM 256M/500M (Apache-2.0);
  - Moondream 2 (Apache-2.0).

  SmolDocling/Granite-Docling (Apache-2.0) на CPU тратят минуты на страницу.
- **Изображения:**
  - удаление фона: u2net/ISNet через rembg (Apache-2.0), BiRefNet lite (MIT);
  - удаление объектов: LaMa (Apache-2.0);
  - глубина: Depth Anything V2 Small (Apache-2.0);
  - сегментация: SAM 2.1 tiny (Apache-2.0);
  - колоризация: DDColor (Apache-2.0);
  - увеличение: Real-ESRGAN (BSD-3; на CPU минуты на мегапиксель), Swin2SR (проверить лицензию).
- **Аудио:** разделение на стемы — Demucs (MIT; 2–6 минут на песню на 2 vCPU); ноты из аудио — basic-pitch (Apache-2.0; крошечная модель, работает и в браузере); шумоподавление — DeepFilterNet (MIT/Apache-2.0) или RNNoise через фильтр ffmpeg `arnndn` (проверить лицензию файла модели).
- **Перевод:**
  - Opus-MT/Marian через CTranslate2 (CC-BY-4.0; пары en↔ru есть; для отсутствующих пар — через английский);
  - пакеты Argos (проверить лицензию каждого пакета);
  - Bergamot в браузере (движок MPL-2.0; лицензии моделей проверять);
  - M2M100 418M (MIT);
  - MADLAD-400 3B (Apache-2.0; медленно).
- **Небольшие LLM** (резюме, перевод с сохранением разметки, запрос на естественном языке → рецепт или SQL, код CAD-модели): Qwen3 0.6B–4B (Apache-2.0), Phi-4-mini (MIT), SmolLM3-3B (Apache-2.0), Granite 4 (Apache-2.0). Исключены Llama, Gemma и LFM2 (собственные лицензии).
- **Текст → изображение:** кандидаты Kandinsky 2.2 (Apache-2.0) и Würstchen v2 (MIT) — проверить лицензии, память и скорость. FLUX.1-schnell и FLUX.2 klein 4B (Apache-2.0) требуют больше 12 ГБ RAM даже квантованными — вне бюджета сервера.
- **Изображение → 3D:** TripoSR (MIT; на CPU около 6 минут по единственному найденному отчёту; память не опубликована). TRELLIS.2 (MIT) работает только на GPU.
- **Защитные модели:** классификатор NSFW для любых генеративных изображений — например, Falconsai/nsfw_image_detection (Apache-2.0); проверить лицензию.

### Ориентиры скорости на 2 vCPU
- llama.cpp Q4_K_M: 1B — около 6–15 токенов в секунду, 3–4B — 3–6, 7–8B — 1–3. Документ на 10 страниц через LLM — десятки минут, только фоновой задачей.
- Распознавание речи: Parakeet/GigaAM в ONNX — в несколько раз быстрее реального времени; faster-whisper small int8 — примерно в 2 раза быстрее реального времени.
- OCR страницы: Tesseract — от 0,2 до 2 секунд; Docling — 2–4 секунды на страницу.

## 4. Автоподбор моделей

### Источники данных (проверено 2026-10-03)
- **Поиск моделей:**
  `GET https://huggingface.co/api/models?pipeline_tag=<tag>&sort=downloads&limit=100&expand[]=safetensors&expand[]=cardData&expand[]=gated&expand[]=library_name&expand[]=tags&expand[]=downloads&expand[]=likes&expand[]=trendingScore&expand[]=lastModified`

  Отдаёт число параметров (`safetensors.total`), лицензию (`cardData.license`), языки (`cardData.language`), признак gated, библиотеку и теги. Список файлов — через `GET /api/models/<id>` (поле `siblings`) или `/tree/<revision>`.
- **Официальные бенчмарки:** `GET https://huggingface.co/api/datasets?filter=benchmark:official` — на дату проверки 48 датасетов. Среди них `hf-audio/open-asr-leaderboard` (WER, меньше — лучше), `allenai/olmOCR-bench` (выше — лучше), `PaddlePaddle/Real5-OmniDocBench`, `llamaindex/ParseBench`, `mteb/*`, `MMMU/MMMU_Pro`, `MME-Benchmarks/Video-MME-v2`.
- **Лидерборд бенчмарка:** `GET https://huggingface.co/api/datasets/<id>/leaderboard` отдаёт `[{rank, modelId, value, verified, ...}]`. Почти все значения — самоотчёты из `.eval_results` репозиториев моделей (`verified: false`).
- **Чего ждать от данных:**
  - одна популярность шумит: в топе trending по распознаванию речи на дату проверки были пайплайн диаризации и модель под Apple MLX;
  - лидеры лидербордов быстро меняются (в топе ASR — модели 2026 года). Поэтому подбор динамический, но всегда ограничен тем, что мы умеем запускать.

### Алгоритм
1. **Задача → кандидаты.** У каждой AI-задачи formular в конфиге есть `pipeline_tag` (один или несколько), список допустимых адаптеров, бенчмарки с направлением метрики, требования к языку и возможностям (например, метки времени для субтитров). Кандидаты — объединение результатов поиска и списка «проверенных семян» для задачи.
2. **Жёсткие фильтры** (нарушил хоть один — исключён):
   - есть адаптер для семейства или формата модели (раздел 5);
   - лицензия из разрешённого списка (`02-constraints.md`, раздел 5);
   - модель не gated;
   - нет пользовательского кода: в `config.json` нет `auto_map`, в тегах нет `custom_code` (иначе мы бы запускали чужой код на сервере);
   - веса только в safetensors, ONNX, GGUF или CTranslate2 — никаких `.bin`, `.pt` и `.pkl` (pickle исполняет код при загрузке);
   - помещается в память: `параметры × байт на параметр (по dtype или квантованию) × 1,3 ≤ бюджет` исполнителя; для браузера бюджет — по `navigator.deviceMemory` и лимитам WebGPU-адаптера;
   - поддерживает нужный язык (по `cardData.language` или явная многоязычность) и нужные возможности.
3. **Оценка:**
   `S = w_b·бенчмарк + w_p·популярность + w_r·свежесть + w_m·измеренная_скорость + w_s·доля_успехов + w_u·отзывы − штрафы`.
   - балл бенчмарка нормализуется с учётом направления метрики; неподтверждённые значения умножаются на 0,8;
   - популярность — `log(downloads) + likes` в нормированном виде;
   - для интерактивных запусков вес скорости выше, для фоновых — вес качества.
4. **Пробный запуск.** При первом выборе модель скачивается (с прогрессом) и прогоняется на встроенном крошечном образце (3 секунды аудио, маленькая картинка, один абзац). Измеряются задержка и пик памяти. Провал — модель попадает в чёрный список с причиной на сутки.
5. **Реестр моделей** — коллекция `formular.models`: `model_id`, закреплённая ревизия (sha коммита), задача, адаптер, лицензия, параметры, размер, языки, оценки, измерения, статус, `last_checked`.
6. **Обновление.** Кандидаты и лидерборды обновляются фоном раз в сутки с кэшем. Модель внутри задачи не меняется; ревизия закрепляется на задачу ради воспроизводимости.
7. **Исследование новых моделей** — только по команде владельца: например, ручной «бенчмарк» новых кандидатов на эталонных образцах.
8. **Ручной выбор пользователем.** Поле с автодополнением по `GET /api/models?search=...` и проверкой теми же жёсткими фильтрами. Лицензионную политику обойти нельзя. Показываются размер скачивания, оценка памяти и времени. Если модель не проходит — объяснение почему.

### Главная оговорка
«Лучшая модель» — лучшая из тех, что умеют запускать наши адаптеры. Новые архитектуры (например, модели на NeMo, которые не экспортированы в ONNX) требуют нового адаптера. Адаптеры — настоящая точка расширения, а алгоритм выбирает среди уже поддержанного.

## 5. Адаптеры

Интерфейс адаптера: `can_run(model_info) → bool`, `estimate(model_info, input) → {ram, seconds}`, `load()`, `run(input, params, progress)`, `unload()`.

Планируемые адаптеры:
- **sherpa-onnx** (Apache-2.0): распознавание речи (Parakeet, Whisper, Zipformer), озвучка (голоса Piper и другие VITS), диаризация. Есть сборка для браузера (WASM).
- **CTranslate2** (MIT): Whisper через faster-whisper, Marian/Opus-MT.
- **ONNX Runtime общий** (MIT): задачи с известной пред- и постобработкой — фон, глубина, OCR (RapidOCR), классификация, LaMa.
- **llama.cpp** (MIT): GGUF-модели LLM. Вариант — бинарник `llama-server` как отдельный процесс (без компиляции при сборке образа) или `llama-cpp-python` (компилируется, сборка дольше).
- **Tesseract** (Apache-2.0): CLI, не модель с HF.
- **transformers pipeline** (Apache-2.0): универсальный, но тянет PyTorch (+1–2 ГБ образа, много памяти). Только если без него не обойтись.
- **diffusers** (Apache-2.0): только для экспериментального «текст → изображение», тоже требует PyTorch.
- **Transformers.js** (Apache-2.0): браузер, модели с ONNX-весами (`library=transformers.js` или папка `onnx/`).

Предпочтение — ONNX, CTranslate2 и GGUF вместо полного PyTorch: меньше образ, меньше память, быстрее старт.

## 6. Кэш моделей и память

- Кэш весов лежит во временном каталоге formular и учитывается в `temp_mb`. Для `speech.transcribe` и `speech.speak` (решения D17 и D18) файлы остаются в кэше с потолком размера, чтобы пример голоса не скачивался при каждом нажатии; диск Space всё равно стирает их при рестарте. Одновременно в память загружается одна речевая модель. Смешанный текст говорит несколькими голосами по очереди, а не всеми сразу.
- В памяти одновременно держится одна тяжёлая модель; выгрузка после N минут простоя. Две больших модели одновременно не загружаются. Перед загрузкой — проверка оценки памяти; если не хватает, задача ждёт или завершается с объяснением.
- Потоки: ONNX Runtime `intra_op_num_threads` 1–2, `OMP_NUM_THREADS`, CTranslate2 `intra_threads` 2, llama.cpp `-t 2`. Процессы инференса — с низким приоритетом (`08-infrastructure.md`).
- Скачивание: только с хостов Hugging Face (разрешить их в `network.allowed_hosts`), с докачкой, проверкой хэшей и закреплённой ревизией.
- Отдельная грабля: `rembg` по умолчанию качает модели с GitHub. Брать модели с HF или явно задавать путь, иначе понадобится ещё один хост в allowlist.

## 7. Безопасность и ограничения

- Никакого pickle, никакого `trust_remote_code`, никакого кода из репозиториев моделей.
- Для любых генеративных изображений — классификатор NSFW и фильтр запросов: Content Policy HF требует помечать или не допускать такой контент.
- Не делаем клонирование голоса, замену лиц, «раздевание» и «оживление» фотографий людей. С 2 декабря 2026 года EU AI Act (ст. 5) запрещает системы, которые генерируют интимные изображения реальных людей без согласия или материалы сексуального насилия над детьми, в том числе когда такой результат «разумно предсказуем» без адекватной защиты. Поэтому любая генерация или редактирование изображений с людьми — только с фильтрами.
- AI-результаты содержат ошибки: в интерфейсе — короткий дисклеймер при первом использовании AI.

## 8. Маркировка AI (решение D7, EU AI Act ст. 50)

Отсрочки для новых функций нет: Digital Omnibus продлил срок машиночитаемой маркировки только для систем, выпущенных до 2 августа 2026 года. Поэтому маркировка обязательна с момента запуска любой AI-операции (`02-constraints.md`, раздел 6).

- **Интерфейс:**
  - единый значок «AI» (свой цвет и иконка) на операции, в превью пути, на задаче и на ассете-результате;
  - иконка `bi-stars` не подходит: в текущем интерфейсе она означает «настройки изменены»;
  - во всплывающей подсказке: модель со ссылкой на HF, ревизия, лицензия (с атрибуцией для CC-BY), где выполняется (сервер или браузер), оценка времени.
- **API:** у каждого шага и задачи поле `ai: {used, task, models: [{id, revision, license}]}`.
- **Метаданные файлов:**
  - изображения — XMP/IPTC `DigitalSourceType = trainedAlgorithmicMedia`; по возможности манифест C2PA (проверить лицензию и зрелость библиотеки c2pa-python);
  - аудио — тег комментария или TXXX; MP4/WebM — теги `comment` и `description`;
  - DOCX/ODT — свойства документа; субтитры — строка-комментарий;
  - JSON — поле `generator`.
- Текст, распознанный из речи или OCR, тоже отмечается как полученный AI, но ненавязчиво: в метаданных, без вставок в сам текст.

## 9. Перевод документов с сохранением стиля и структуры

### Принцип
Документ не превращается в текст. Перевод идёт внутри его разметки:
1. Документ разбирается в дерево (абзацы, ячейки, надписи, сноски, колонтитулы, заметки к слайдам, подписи к диаграммам).
2. Каждый абзац — сегмент. Фрагменты внутри абзаца с разным форматированием (жирный, курсив, ссылка, цвет) заменяются парными метками: `Нажмите <1>кнопку</1> и <2>подождите</2>`. Непереводимое (код, URL, числа, формулы, плейсхолдеры, имена полей) защищается метками-пустышками.
3. Сегмент переводится движком, который обязан вернуть метки.
4. Перевод раскладывается обратно по фрагментам форматирования.
5. Если метки потерялись (часто бывает у MT-моделей), перевод разбивается по меткам эвристикой: стиль фрагмента, покрывающего большую часть абзаца, применяется ко всему сегменту, а редкие стили по возможности переносятся по словам.

### Форматы
- **DOCX, PPTX, XLSX:** python-docx (MIT), python-pptx (MIT), openpyxl (MIT) или прямой разбор XML через lxml.
- **ODT, ODP, ODS:** разбор XML (odfpy — проверить лицензию) или круг через LibreOffice в DOCX и обратно.
- **EPUB, HTML:** lxml, перевод текстовых узлов.
- **Markdown:** разбор в AST.
- **SRT, VTT, ASS:** pysubs2 (MIT), перевод по репликам с сохранением таймингов и тегов стиля ASS.
- **PDF — самый сложный.** По решению D15 брать BabelDOC (AGPL-3.0). Запасной вариант, если BabelDOC не уложится в память Space: PDF → DOCX → перевод → PDF с предупреждением о потере вёрстки.

### Вёрстка после перевода
- Русский текст на 15–30% длиннее английского. В PPTX включать автоподбор размера (`normAutofit`), в XLSX — подбирать ширину колонок, в DOCX — ничего не делать (поток текста).
- Шрифты сохраняются; если в шрифте нет нужных глифов — подставлять похожий и предупреждать.
- RTL-языки: направление абзаца и выравнивание.

### Движки
- **Быстро:** Opus-MT через CTranslate2 (страницы в минуту на CPU). Определение языка — `lingua` или `langdetect` (Apache-2.0). fastText `lid.176` не брать: CC-BY-SA.
- **Качественно:** LLM (Qwen3 1.7B–4B) для сегментов с метками и для «режима качества». Медленно (3–6 токенов в секунду на 4B), только фоновой задачей с прогрессом по абзацам и контрольными точками.
- Глоссарий пользователя (термины, которые нельзя переводить или надо переводить определённым образом).
- Вариант вывода: в исходном формате или двуязычный (оригинал и перевод рядом).

## 10. Декомпиляция

- **Детекция:** PE, ELF, Mach-O, DEX, class/JAR/APK, .NET (метаданные), pyc, wasm, байткод Lua, SWF — по сигнатурам; LIEF (Apache-2.0) для метаданных исполняемых файлов.
- **Байткод (хорошее качество, дёшево):**
  - Java/JAR — CFR (MIT) или Vineflower (Apache-2.0); Android APK/DEX — jadx (Apache-2.0);
  - .NET — ilspycmd (MIT; нужен рантайм .NET);
  - Python .pyc — pycdc (GPL-3.0 CLI; новые версии Python поддерживаются частично);
  - WebAssembly — WABT `wasm2wat` и `wasm-decompile` (Apache-2.0);
  - Lua — unluac (проверить лицензию); SWF — JPEXS (GPL-3.0).

  Большинству инструментов для JVM нужна Java (около 200 МБ в образе).
- **Нативный код:**
  - Ghidra headless (Apache-2.0; JDK 21; минимум 4 ГБ RAM, рекомендуется 8; около 1 ГБ на диске) — на нашем worker на грани;
  - легче — rizin с rz-ghidra (LGPL-3.0);
  - дизассемблирование — Capstone (BSD-3).

  Лимиты: размер бинарника (например, до 20 МБ), `-analysisTimeoutPerFile`, `MAXMEM` 1,5–2 ГБ, `-max-cpu 1`.
- **Результат:**
  - дерево исходников архивом и просмотр файлов в интерфейсе;
  - JSON с метаданными (секции, импорты, экспорты, строки);
  - листинг дизассемблера.
- **AI-доработка (эксперимент):** модели семейства LLM4Decompile переписывают псевдокод Ghidra в читаемый C. Лицензия зависит от базовой модели чекпойнта — брать только пермиссивный. Небольшие функции, фоновая задача, пометка AI.
- **Политика:** только статический анализ, ничего не запускается; короткий срок жизни; загруженные бинарники и результаты не раздаются публично; дисклеймер о законности (зависит от юрисдикции и цели).
- **Порядок внедрения:** сначала инструменты, которым не нужна Java. JRE в образ не ставить, пока нет отдельного расчёта места, памяти и CPU (решение D11). Ghidra — последней и только если расчёт покажет, что она помещается.

## 11. Процедурные пайплайны вместо невозможной генерации

- **«Видео из текста»:** текст → сегменты сценария (правила или небольшая LLM) → озвучка → слайды (типографские или из «текст → изображение», если оно доступно) → ffmpeg: панорамирование и масштаб, переходы, вшитые субтитры. Помечается как AI, если озвучка или картинки — AI.
- **«Музыка из текста»:** LLM или правила генерируют ABC/MIDI → music21 → FluidSynth с пермиссивным SoundFont (проверить лицензию) → аудио.
- **«3D из текста»:** LLM пишет код CadQuery (Apache-2.0) или OpenSCAD (GPL CLI) → рендер в STL/GLB → превью в браузере через three.js. Подходит для CAD-подобных объектов; качество небольших моделей ограничено.
