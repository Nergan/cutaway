# Публичный API

Живой formular отдаёт REST ниже. Разделы 1–6 описывают целевую переработку и в текущем коде не реализованы.

## Сейчас

Префикс хаба — `/formular`. Ошибки — JSON `{"detail": "..."}`. Запись больше предела — `413`, и текст называет оба размера: `note.txt is 51.2 MiB. The maximum is 32.0 MiB.` На профиле hf предел запроса `33554432` байт (32 МиБ); один файл чуть меньше, потому что к телу multipart добавляется рамка. Точное значение для файла отдаёт `max_file_bytes`.

| Метод и путь | Назначение |
|---|---|
| `GET /api` | Пределы и карта маршрутов: `max_upload_bytes`, `max_file_bytes`, `max_output_bytes` |
| `POST /api/files` | Создать файлы. Поле multipart `files`, можно несколько. `201` и `{"files":[{"id","filename","size","format","allowed_targets"}]}`. Неподдерживаемый формат остаётся в этом списке с полем `error` |
| `GET /api/files/{id}` | Метаданные уже загруженного файла |
| `POST /api/files/{id}/conversions` | Конвертация. JSON `{"to":"mp3","audio":{},"video":{},"ffmpeg":"...","merge_id":"...","merge_loop":false}`. Ответ — байты результата и `Content-Disposition`. Сессии нет — соединение держится до конца |
| `GET /api/voices` | Голоса озвучки и пометка AI |
| `GET /api/voices/{id}/sample` | Короткий WAV этого голоса |

`POST /api/upload` и `POST /api/convert` делают то же самое, что создание файла и конвертация: их вызывает текущая страница. У конвертации поля формы `file_id`, `to_format`, `audio_opts`, `video_opts`, `custom_ffmpeg`, `merge_id`, `merge_loop` (`true` / пусто).

Пример:

```bash
curl -s -F "files=@note.txt" "$ORIGIN/formular/api/files"
curl -s -X POST "$ORIGIN/formular/api/files/$ID/conversions" \
  -H "Content-Type: application/json" \
  -d '{"to":"md"}' -o note.md
```

Страница до выбора файла показывает `max_file_bytes`. Если файл больше, браузер сначала снимает только то, что не меняет картинку и звук: комментарий JPEG, текстовые чанки PNG, более плотная упаковка ZIP. Видео и звук так не уменьшаются: их байты и есть содержимое. Файл, который после этого всё ещё больше предела, не отправляется.

## 1. Допустимость

Публичный API политике Hugging Face не противоречит: Gradio-Spaces по умолчанию отдают API, а прямых запретов на API у Docker Spaces нет. Рискованно другое — то, что делает Space похожим на прокси, файлообменник или источник массовой активности. Поэтому:
- **никакого импорта по URL и никаких webhook'ов** на адреса от пользователя — только загрузка файлов и опрос состояния;
- результаты живут не дольше срока рабочего пространства (≤ 24 часа), без публичных списков;
- лимиты на частоту, размер, суммарное время задач; proof-of-work для анонимных клиентов;
- AI через API выполняется на тех же условиях, что в интерфейсе: только на сервере formular (решение D2).
- Сотрудники HF считают Spaces площадкой для демо, а не продакшен-бэкендом (ответ на форуме, 2023). Поэтому лимиты API держать скромными, а массовое использование не поощрять.
- formular раздаёт файлы по ссылкам, поэтому нужен способ пожаловаться на содержимое (DSA, ст. 16): эндпоинт или форма и процедура удаления.

## 2. Принципы

- Один реестр операций обслуживает UI, REST и MCP (`03-architecture.md`).
- Версионирование: `/formular/api/v1/...`; старые `/formular/api/upload` и `/formular/api/convert` работают поверх нового ядра, пока их использует старый интерфейс, затем удаляются.
- По умолчанию асинхронно: создать задачу, опрашивать, скачать результат. Для маленьких входов есть синхронный короткий путь.
- OpenAPI генерируется FastAPI: `/formular/api/v1/openapi.json`.
- Через API доступны только операции с серверным исполнителем. Браузерные операции в описании помечены `executors: ["browser"]` и через API не запускаются; если у операции есть и серверная реализация, используется она.
- Ошибки — JSON вида `{"error": {"code": "...", "message": "...", "details": {...}}}` с корректными HTTP-статусами; при 429 и 503 — заголовок `Retry-After`.
- Все запросы короткие (секунды), потому что прокси хаба ограничивает параллелизм и время запроса (`02-constraints.md`, раздел 2).

## 3. Эндпоинты

| Метод и путь | Назначение |
|---|---|
| `GET /operations` | Реестр операций: роли входов, параметры (JSON Schema), выходы, исполнители, потери, флаг AI, оценка стоимости. Фильтры `?kind=`, `?format=` |
| `GET /operations/{id}` | Одна операция |
| `GET /formats` | Форматы и виды |
| `POST /plan` | По форматам или ассетам и цели (формат или операция) вернуть варианты рецептов с оценками — «что можно сделать с этим» |
| `POST /workspaces` | Создать рабочее пространство → `{id, expires_at}` |
| `GET /workspaces/{id}` | Ассеты и задачи; поддерживает `ETag` / `If-None-Match` для опроса |
| `DELETE /workspaces/{id}` | Удалить всё сразу |
| `POST /workspaces/{id}/assets` | Загрузить файл до 32 МиБ одним запросом |
| `POST /workspaces/{id}/uploads` → `PUT .../uploads/{uid}/parts/{n}` → `POST .../uploads/{uid}/complete` | Загрузка больших файлов кусками по ≤ 32 МиБ, с докачкой |
| `GET /assets/{id}/content` | Скачать; поддерживает `Range`. Файлы больше 128 МиБ — только частями |
| `DELETE /assets/{id}` | Удалить ассет |
| `POST /workspaces/{id}/jobs` | Запустить рецепт → задача |
| `GET /jobs/{id}` | Состояние, прогресс, выходы, ошибки, сведения об AI |
| `POST /jobs/{id}/cancel` | Отменить |
| `POST /convert?wait=30` | Синхронный короткий путь: файл и цель в одном запросе; если готово за `wait` секунд — сразу файл, иначе ссылка на задачу |
| `GET /models?task=...` | Текущая выбранная модель и кандидаты для AI-задачи |
| `POST /models/check` | Проверить модель, указанную пользователем: лицензия, формат весов, размер, совместимость |
| `POST /reports` | Жалоба на содержимое по ссылке (механизм уведомлений по DSA, ст. 16) |

Префикс у всех путей — `/formular/api/v1`.

## 4. Рецепт в API

Тот же JSON, что в `03-architecture.md`, раздел 2:

```json
{
  "steps": [
    {"id": "trim", "op": "media.trim", "inputs": {"source": "asset:91aa"}, "params": {"start": "00:00:05", "end": "00:01:00"}},
    {"id": "mix", "op": "video.replace_audio", "inputs": {"video": "step:trim", "audio": "asset:7f3c"}, "params": {"shortest": true}},
    {"id": "out", "op": "convert", "inputs": {"source": "step:mix"}, "params": {"to": "mp4"}}
  ],
  "outputs": ["out"]
}
```

Ответ задачи содержит `steps[].ai` — например, `{"used": true, "task": "asr", "models": [{"id": "...", "revision": "...", "license": "mit"}]}`.

## 5. Доступ и лимиты

- **Анонимно:** лимиты по IP, по рабочему пространству и на суммарное время задач; при создании задачи — proof-of-work (подход netlazy: SHA-256 с заданным числом нулей, сложность растёт под нагрузкой; готовая альтернатива без внешнего сервиса — виджет ALTCHA под MIT). Proof-of-work нужен только на создание задач, не на опрос состояния.
- **API-ключи (необязательно):** выдаёт владелец, в Mongo хранятся только хэши. Ключ повышает лимиты и снимает proof-of-work. Без ключа API работает с анонимными лимитами.
- **Рабочее пространство** — это и есть право доступа: знающий `workspace_id` видит его метаданные. Шифрование зеркала — по ключу из заголовка `X-Formular-Key`, если клиент его передал (`03-architecture.md`, раздел 7).
- Квоты по умолчанию задаются переменными `FORMULAR_*`, на HF — через `env_defaults` (`08-infrastructure.md`).

## 6. MCP (необязательно, этап 9)

- Спецификация MCP от 2026-07-28: Streamable HTTP без сессий и расширение Tasks для долгих операций — прямой аналог задачи formular. У CloudConvert и Transloadit MCP-серверы уже есть.
- Лучше 6–8 курируемых инструментов, чем автогенерация из OpenAPI: `list_operations`, `describe_operation`, `plan`, `upload` (base64 до небольшого лимита), `create_job` (возвращает task), `get_job`, `download_url`.
- Те же лимиты и правила, что у REST; путь — например, `/formular/mcp`.
