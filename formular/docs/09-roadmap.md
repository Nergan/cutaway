# План работ

Этапы упорядочены по зависимостям. Каждый этап должен оставлять formular рабочим и не ломать экосистему. Владелец разрешил начать (решение D9). После каждого этапа обновлять статус в этой таблице.

## Этап 0. Стабилизация текущего formular
**Цель:** убрать текущие сбои, не меняя концепцию.
- Пересчитывать видимость вкладки Merge при появлении новых файлов; кандидатов брать по формату от сервера (P1, P2).
- Убрать утечку обработчиков: повторный `initCustomSelect(bulkTarget)` и обработчики `document` у каждой карточки (P7).
- Ограничить потоки ffmpeg и запускать его с низким приоритетом; проверить на Space, убивает ли супервизор длинные кодирования (P6); при необходимости — правка политики CPU (`08-infrastructure.md`, 2.2).
- Поднять `max_concurrency` для formular и развязать тяжёлые процессы (`08-infrastructure.md`, 2.3) (P5).
- Понятные сообщения об ошибках вместо `str(e)`; ошибки параметров — 422 (P10).
- Белый список пользовательских флагов ffmpeg (P9); XML через `defusedxml` (P15).
- Проверить вывод кириллицы в PDF через LibreOffice.

**Приёмка:** аудио накладывается на видео при любом порядке загрузки; конвертация длинного видео не валит worker и не блокирует страницу для других пользователей; при 50 выделениях подряд число обработчиков не растёт; все тесты зелёные.

## Этап 1. Реестр операций и планировщик
**Цель:** единый источник правды вместо `ALLOWED_CONVERSIONS` и `DIRECT_EDGES`.
- Модель видов, форматов, операций с ролями, параметрами (JSON Schema), исполнителями, стоимостью и потерями (`03-architecture.md`, раздел 2).
- Перенести все текущие конвертации и опции ffmpeg (обрезка, кроп, масштаб, фильтры, темп, реверберация, бас) в операции; `merge` — в `video.replace_audio`, `video.mix_audio`, `image.audio_to_video`.
- Взвешенный поиск пути с несколькими вариантами; опции применяются к нужному шагу, а не только к последнему.
- Детекция формата с уверенностью и альтернативами.
- Внутренние эндпоинты `GET /operations`, `POST /plan`; старые `/api/upload` и `/api/convert` работают поверх реестра.

**Приёмка:** все конвертации из текущего README работают через реестр, результаты совпадают; тесты на планировщик (пути, недостижимые цели, роли нескольких входов); тесты `test_hosting_policy.py` обновлены, если менялся `converter.py`.

## Этап 2. Рабочее пространство, задачи, ссылки
**Цель:** закрыл вкладку — вернулся по ссылке в течение суток.
- Коллекции Mongo, очередь на арендах, heartbeat, восстановление после рестарта, отмена, контрольные точки (`03-architecture.md`, раздел 5).
- Локальное хранение с подбюджетами и очистка по истечении срока. Зеркала в Cloudinary нет (решение D13).
- Ссылка `/formular/w/<id>#k=<key>`, история рабочих пространств в `localStorage`.
- Опрос прогресса с `ETag`.
- Гигиена ссылок (`03-architecture.md`, раздел 7):
  - в базе — хэш идентификатора;
  - `Referrer-Policy` и `noindex`, ответ 410 после истечения срока;
  - скрипты с собственного origin или с SRI, без `@latest`;
  - фрагмент с ключом убирается из адресной строки.
- Выдача файлов только вложением с `nosniff`; превью пользовательского HTML/SVG — только в песочнице (`03-architecture.md`, раздел 10).
- Механизм жалоб на содержимое (`02-constraints.md`, раздел 6).
- Инфраструктура: переменные окружения Mongo, маркер занятости или `idle_timeout_seconds = 0`, подбюджеты диска (`08-infrastructure.md`). Секрет `FORMULAR_HF_TOKEN` и доступ к Cloudinary не добавлять (D13, D14).

**Приёмка:** задача продолжается после закрытия вкладки и после рестарта worker; после push в `main` пользователь видит состояние своих задач (готово, восстановлено или «нужно загрузить заново»); через 24 часа данные удаляются с диска и из Mongo; на M0 formular не превышает 10 операций в секунду в среднем.

## Этап 3. Новый интерфейс
**Цель:** UX из `06-ux.md` с сохранением всего, что перечислено в `01-current-state.md`, раздел 2.
- Рабочее пространство, модель выделения (лассо, Shift/Ctrl-клик, стрелки), панель действий по выделению, «Конвертировать в…» с превью пути, перетаскивание для комбинаций, палитра команд, панель задач, ссылка, QR-код и таймер, пометка AI, горячие клавиши, мобильная версия, доступность.
- Решить, нужна ли сборка фронтенда; если да — `package.json` и `npm_build = true`.

**Приёмка:** каждое действие доступно мышью, клавиатурой и касанием; сценарии из `06-ux.md`, раздел 10, проходят вручную; производительность при 200 карточках приемлемая.

## Этап 4. Браузерный исполнитель
**Цель:** тяжёлое и большое — на железе пользователя.
- Web Workers, проверка возможностей, выбор исполнителя в планировщике.
- Медиа — Mediabunny + WebCodecs, запасной вариант — ffmpeg.wasm; изображения — jSquash, magick-wasm, libheif-js; PDF — pdf.js и живой форк pdf-lib; таблицы — SheetJS или DuckDB-WASM; архивы — libarchive.js или fflate.
- Cross-origin isolation только для страниц formular (`08-infrastructure.md`, раздел 4).
- Явное предупреждение «не закрывайте вкладку» для браузерных шагов.

**Приёмка:** смена контейнера, обрезка и замена дорожки у видео на 2 ГБ проходят в браузере без загрузки на сервер; без WebGPU и изоляции всё откатывается на рабочие варианты.

## Этап 5. Расширение каталога без AI
Операции P1 из `07-catalog.md`: операции с PDF, субтитры, шрифты, диаграммы, QR, кодировки текста, «сжать до N МБ», слайд-шоу, архив как коллекция, массовое заполнение шаблона, заполнение PDF-форм и др. Комбинации нескольких файлов — полноценные операции. Новые apt-пакеты — по таблице из `08-infrastructure.md`.

**Приёмка:** у каждой новой операции есть описание в реестре, тест на образце и запись в каталоге.

## Этап 6. Основа AI и первые AI-операции
- Реестр моделей, автоподбор, адаптеры (sherpa-onnx, CTranslate2, ONNX Runtime), кэш моделей и управление памятью, маркировка AI (`04-ai.md`).
- Операции: распознавание речи и субтитры, OCR, подписи к изображениям, документ → Markdown, озвучка, удаление фона, глубина — на сервере и в браузере.
- Инфраструктура: сеть к хостам HF, `temp_mb`, `fsize_mb`, `memory_mb`.

**Приёмка:** модель выбирается автоматически и проходит все жёсткие фильтры; ручной выбор модели проверяется и объясняет отказ; AI-результаты помечены в UI, API и метаданных; worker не превышает лимит памяти при последовательных задачах с разными моделями.

## Этап 7. Перевод документов и субтитров
По разделу 9 в `04-ai.md`: DOCX, PPTX, XLSX, ODF, EPUB, HTML, Markdown, SRT/VTT/ASS; PDF — отдельным решением по лицензии BabelDOC или своим способом.

**Приёмка:** на эталонном DOCX с жирным и курсивом внутри предложений, таблицей, сносками и колонтитулами форматирование сохраняется; PPTX не вылезает за рамки блоков.

## Этап 8. Декомпиляция
Сначала байткод и метаданные (решение о Java в образе), затем rizin, затем Ghidra и экспериментальная AI-доработка (`04-ai.md`, раздел 10).

**Приёмка:** JAR, APK, .NET DLL, pyc и wasm превращаются в архив исходников; загруженное нигде не запускается.

## Этап 9. Публичный API и MCP
По `05-api.md`: версия `v1`, OpenAPI, лимиты, proof-of-work для анонимов, необязательные API-ключи, документация с примерами; при желании — MCP-сервер.

**Приёмка:** любой серверный сценарий из интерфейса воспроизводится через API тем же JSON рецепта.

## Этап 10. Эксперименты
«Текст → изображение» на пермиссивных моделях, «изображение → 3D» (TripoSR), «текст → 3D» через код CAD-модели, процедурные «видео из текста» и «музыка из текста», разделение на стемы, аудио → MIDI. Каждый эксперимент включается, только если укладывается в бюджет памяти и времени на Space или выполняется в браузере.

## Риски

| Риск | Вероятность | Мера |
|---|---|---|
| HF отменит legacy-условия для старых Docker Spaces | средняя | Браузерная часть formular способна работать из статического Space; серверное — опционально |
| Ложное срабатывание автосканера HF ставит на паузу весь Space | средняя | Соблюдать список триггеров, не добавлять загрузку по URL, проверять `hosting_policy` перед каждым коммитом |
| Formular отнимает CPU и память у соседей | высокая без мер | Низкий приоритет, ограничение потоков, подбюджеты, проверка соседей после изменений |
| Лимиты Mongo M0 (512 МБ, 100 оп/с) общие с соседями | средняя | Маленькие документы, редкие записи прогресса, TTL |
| Кредиты Cloudinary общие с netlazy и soon | снято решением D13 | Formular в Cloudinary не пишет |
| Лицензии моделей меняются | средняя | Закреплять ревизию, перепроверять лицензию при обновлении реестра |
| Нужная модель не поддержана адаптерами | высокая | Адаптеры как точка расширения; честное «недоступно» в UI |
| Размер образа и время сборки растут | высокая | Пакеты по этапам, без PyTorch до этапа 10 |
| Браузерные API различаются (Safari, iOS) | средняя | Проверка возможностей и откат на сервер или однопоточные варианты |
| Действие с Space (пауза, смена железа, перенос, factory rebuild) лишает его legacy-условий | низкая при соблюдении правил | Запреты из `02-constraints.md`, раздел 1; любые изменения настроек Space — только с согласия владельца |
| Пользовательский HTML или SVG выполняется в общем origin и крадёт данные соседних проектов | высокая без мер | Выдача только вложением, `nosniff`, превью в песочнице (`03-architecture.md`, раздел 10) |
