# Formular: проектная документация переработки

Этот каталог описывает, что нужно сделать с formular, какие у этого есть проблемы и ограничения и как их решать. Основан на исследовании от 2026-10-03: код проекта и экосистемы, проверки живого Space и API Hugging Face, веб-источники (сводка — в `10-research.md`).

**Статус:** владелец 2026-10-04 разрешил начать реализацию по `09-roadmap.md`. После просмотра сайта переработка этапов 0–2 убрана из кода (решение D17): живой formular — прежний интерфейс плюс распознавание речи и озвучка. Документы этапов описывают дальнейшую цель, а не текущий код.

## Цель

Превратить formular из конвертера «один файл → один формат» в максимальный any-to-any конвертер, где грань между конвертацией и преобразованием данных почти стирается:

- все загруженные файлы и все результаты лежат в общем рабочем пространстве; интерфейс показывает, что можно сделать с файлом и с комбинацией файлов (видео + аудио → замена дорожки, картинка + аудио → видео, шаблон + таблица → пачка документов);
- операции соединяются в цепочки; результат любой операции — новый файл, с которым можно работать дальше;
- долгие операции выполняются фоновыми задачами; пользователь может закрыть вкладку и вернуться по временной ссылке, пока не истёк срок;
- весь серверный функционал доступен через API;
- AI-операции явно помечены; модели подбираются автоматически, пользователь может указать свою;
- UX не хуже текущего: лассо, горячие клавиши, локальные превью, живое превью эффектов.

## Решения, которые ждут владельца

1. Приём жалоб на содержимое (по DSA, ст. 16) и регистрация DMCA-агента (по желанию, для США). Это не то же самое, что маскировка файлов от стороннего хранилища: маскировка скрывает байты от провайдера, а жалоба — способ третьего лица попросить удалить конкретное рабочее пространство. При D13 файлы и так живут только на диске Space и не дольше суток. Нужно явное «да» или «нет» на короткую форму «пожаловаться», которая удаляет пространство. (`02-constraints.md`, раздел 6.)

## Глоссарий

- **Рабочее пространство (workspace)** — набор файлов и задач одного пользователя, доступный по временной ссылке; живёт не дольше 24 часов.
- **Ассет (asset)** — любой файл в рабочем пространстве: загруженный или полученный операцией. Помнит своё происхождение.
- **Вид (kind)** — смысловой тип данных: документ, таблица, изображение, аудио, видео, субтитры, 3D-модель, архив-коллекция и т. д.
- **Формат (format)** — конкретная сериализация вида: `mp4`, `docx`, `glb`.
- **Операция (operation)** — типизированное действие с ролями входов, параметрами и выходами: `convert`, `video.replace_audio`, `pdf.merge`, `audio.transcribe`.
- **Роль входа** — именованный слот операции: `video`, `audio`, `watermark`, `template`, `data`.
- **Исполнитель (executor)** — где выполняется шаг: браузер пользователя или сервер (CPU Space).
- **Цепочка / рецепт (recipe)** — граф шагов-операций; один и тот же JSON для UI и API.
- **Задача (job)** — запуск рецепта на сервере с очередью, прогрессом и восстановлением после рестарта.
- **Коллекция** — ассет, содержащий другие ассеты: архив, многостраничный PDF, набор кадров видео. Операции над элементом можно применить ко всем элементам коллекции.
- **Адаптер модели** — код, который умеет запускать определённое семейство моделей для определённой задачи.
- **Ссылка-ключ (capability link)** — неугадываемая ссылка на рабочее пространство; ключ шифрования хранится во фрагменте URL после `#` и не попадает на сервер сам по себе.
