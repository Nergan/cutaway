# netlazy

[Read in English (README.md)](./README.md)

`netlazy` — это независимое приложение для знакомств и нетворкинга, созданное для работы без привязки к внешним провайдерам авторизации, SMS-шлюзам или сервисам подтверждения почты. Аутентификация полностью основана на локально генерируемых парах ключей и криптографических подписях, что делает систему автономной.

---

## Основные особенности

*   **Независимая аутентификация**: Аккаунт — это локально созданные ключи Ed25519 и ML-DSA-65. Запросы подтверждаются этими подписями, без пароля, стороннего входа и серверной сессии.
*   **Обфускация медиафайлов «на лету»**: Загружаемые файлы хранятся в виде публичной обложки низкого разрешения с прикрепленной зашифрованной частью. Оригинальный файл расшифровывается клиентом «на лету» при просмотре, защищая контент от прямого скачивания из хранилища CDN.
*   **Ограничение частоты запросов через Proof of Work**: Чтобы предотвратить спам и массовые регистрации без использования сторонних CAPTCHA-сервисов, платформа требует от клиентов решения криптографических задач (Proof of Work) перед выполнением важных действий.
*   **Система рукопожатий**: Взаимное согласие устанавливается с помощью прогрессивных типов «рукопожатий» (Share, Exchange, Demand и Mutual), которые определяют условия раскрытия контактных данных.

## Структура проекта

*   `domain/` — Основные бизнес-модели и абстракции репозиториев.
*   `application/` — Сервисы сценариев использования (аутентификация, профили и рукопожатия).
*   `infrastructure/` — Репозитории MongoDB, интеграция с CDN и обработка медиафайлов.
*   `presentation/` — Роутеры FastAPI и валидация криптографических подписей запросов.
*   `frontend/` — Клиентская часть (SPA) на Vue 3 и Vite с поддержкой сборки нативного приложения через Capacitor.

## API

Хаб отдаёт приложение на `/netlazy`. JSON лежит под `/netlazy/api`. `GET /netlazy/api` перечисляет префиксы групп. Страницы `/netlazy/profile`, `/feed`, `/inbox`, `/privacy` и `/welcome` отдают веб-клиент. Стороннему клиенту нужны только JSON-маршруты ниже.

Сессии и cookie нет. Каждый запрос аккаунта несёт собственную подпись. Тела JSON идут с `Content-Type: application/json`. Загрузка медиа передаёт сырые байты файла. Ошибка имеет вид `{"detail": "..."}`.

### Подпись

У аккаунта два открытых ключа. Их отправляют один раз при регистрации:

* открытый ключ Ed25519 в PEM (`SubjectPublicKeyInfo`);
* открытый ключ ML-DSA-65: hex сырых 1952 байт.

`user_id` — это hex SHA-256 от DER-формы Ed25519 (`SubjectPublicKeyInfo`) и следом сырых байт ML-DSA-65. `user_id` хранится у клиента и называет подписанта. Это не адрес чужой анкеты.

Каждый подписанный запрос передаёт:

| Заголовок | Значение |
| --- | --- |
| `X-User-Id` | `user_id` |
| `X-Timestamp` | Секунды Unix. Сервер принимает значение в пределах 120 секунд от своих часов. |
| `X-Nonce` | Новая строка. Повтор в течение примерно пяти минут даёт 401. |
| `X-Body-Hash` | Hex SHA-256 сырого тела. Пустое тело — это SHA-256 от нуля байт. |
| `X-Signed-Path` | Путь запроса, включая `/netlazy`, без query. |
| `X-Signature-Ed25519` | Обычный base64 подписи Ed25519. |
| `X-Signature-MLDSA` | Обычный base64 подписи ML-DSA-65. |
| `X-Fingerprint` | Необязательная метка клиента. Регистрация и цепочечные запросы её запоминают. |

Обе подписи покрывают один и тот же текст в UTF-8. Три вида текста нельзя подменять друг другом.

**Чтение** (`PQDA-READ-v1`). Так подписываются `GET /profile/me`, `GET /inbox`, `GET /push/preferences`, `POST /feed/search` и `GET /feed/form/{slug}`, если передан `X-User-Id`. Цепочка не двигается, в ответе нет `X-Next-Anchor`.

```text
PQDA-READ-v1
METHOD
/netlazy/api/inbox

1710000000
nonce
e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855
```

Пустая строка — это сырой query. У `POST /feed/search` query пустой, поэтому строка остаётся пустой. Настоящий query пишется без начального `?`, байт в байт как в запросе.

**Цепочка** (`PQDA-v1`). Так подписывается каждое изменение: анкета, медиа, ссылки, рукопожатия, смена ключей и удаление аккаунта. Заголовок `X-Chain-Anchor` содержит якорь, который сервер ещё помнит (последние пять). Канонический текст заканчивается этим якорем:

```text
PQDA-v1
METHOD
/netlazy/api/profile/me

1710000000
nonce
body-hash
previous-anchor
```

Успешный цепочечный ответ ставит `X-Next-Anchor`. Его нужно сохранить и отправить следующим якорем. Серверное значение — hex SHA-256 от `PQDA-CHAIN-v1|` и далее `previous-anchor|user_id|METHOD|signed-path|body-hash|nonce|timestamp`. Цепочечные запросы одного аккаунта отправляйте по одному. Параллельный запрос с тем же якорем может выпасть из окна в пять шагов и получить `409` с текстом `Execution trace broken or outdated`.

**Восстановление якоря** (`PQDA-ANCHOR-v1`). Только `GET /auth/anchor`. В этом тексте нет строки query и нет якоря:

```text
PQDA-ANCHOR-v1
GET
/netlazy/api/auth/anchor
1710000000
nonce
body-hash
```

Ответ: `{"current_anchor": "..."}`. После `409` возьмите его и повторите цепочечный запрос с новым nonce и временем. Сам этот вызов цепочку не двигает.

`401` с текстом `Unknown user` значит, что ключи не зарегистрированы. Остальные ошибки подписи — `401` с текстом `Invalid authentication credentials`. `403` с текстом `banned` значит, что заблокированы аккаунт, адрес или отпечаток.

### Proof of work

`POST /auth/register` и `POST /inbox/handshakes` дополнительно требуют доказательство работы.

1. `GET /security/challenge` возвращает `{"challenge_id", "difficulty"}`. Маршрут без подписи. Обычная сложность — 4.
2. Найдите десятичный nonce, при котором hex SHA-256 от строки `challenge_id + nonce` начинается с `difficulty` нулей.
3. Передайте `X-Challenge-Id` и `X-Pow-Nonce` вместе с защищённым запросом.

Задача одноразовая и живёт около пяти минут. Нет решения или оно неверное — `400` с текстом `Invalid or missing Proof of Work`.

### Что можно узнать о другом человеке

Поиск ленты, анкета по ссылке и анкета внутри входящих отдают только публичную анкету:

```json
{
  "id": "публичный id",
  "bio": "",
  "tags": [],
  "media": [{ "url": "", "media_type": "image", "blur": false }],
  "audio": null,
  "contacts": [{ "type": "email", "value": "open@example.com" }],
  "form": "my-link",
  "media_key": "base64"
}
```

`id` — случайный публичный идентификатор, он хранится у анкеты. Его передают в `seen_ids` и как `receiver_id`. Это не `user_id`. Приватных контактов, идентификатора аккаунта, даты создания анкеты, счёта совпадения и полного списка ссылок в ответе нет. `form` — основная публичная ссылка либо `null`.

`media_key` — обычный base64 32-байтового ключа AES-GCM. Эти байты импортируются как сырой ключ AES-GCM. Файл в хранилище устроен так: обложка низкого разрешения, затем байты `||NLZ_PAYLOAD||`, затем 12-байтовый nonce, затем шифртекст. `media_type` бывает `image`, `video` или `audio`.

`GET` и `PUT /profile/me` возвращают владельцу его собственную запись и сверх публичных полей: `user_id`, `media_id`, `created_at`, `score`, контакты с `is_private`, `forms` и `primary_form`. Прочитать и изменить это может только подпись того же аккаунта.

### Маршруты

Индексы без подписи (`GET /auth`, `/profile`, `/feed`, `/tags`, `/security`) указывают на маршруты своей группы. `GET /inbox` — это сами входящие, а не индекс.

**Аккаунт**

| Метод и путь | Доступ | Тело и результат |
| --- | --- | --- |
| `GET /auth/footprint-check` | нет | `{"has_accounts": true\|false}`, если этот адрес или `X-Fingerprint` уже есть у какого-то аккаунта. |
| `POST /auth/register` | proof of work | `{"ed25519_public_pem", "mldsa_public_hex"}`. `201` возвращает `user_id`, `genesis_anchor` и сообщение. `400`, если ключи неверны или уже зарегистрированы. Начальный якорь — hex SHA-256 от `PQDA-CHAIN-v1\|genesis\|` и `user_id`. |
| `GET /auth/anchor` | восстановление якоря | `{"current_anchor"}`. |
| `POST /auth/rotate` | цепочка | `{"new_ed25519_public_pem", "new_mldsa_public_hex"}`. Возвращает `new_user_id` и `new_anchor`. У анкеты сохраняются публичный id и материал ключа медиа. Прежние рукопожатия удаляются. `X-Next-Anchor` — новый начальный якорь. |
| `DELETE /auth/account` | цепочка | `204`. Удаляет аккаунт, анкету и рукопожатия. |

**Анкета.** Маршруты владельца возвращают его запись. `GET /profile/me` — чтение. Остальные маршруты анкеты идут по цепочке.

| Метод и путь | Тело и результат |
| --- | --- |
| `PUT /profile/me` | `{"bio", "tags", "contacts": [{"type", "value", "is_private"}]}`. Текст до 500 символов. Тегов не больше 50, и каждый должен быть в каталоге. Контактов не больше 20. `type` — это `email`, `link`, `phone` или `unknown`. Значение контакта до 500 символов. Неизвестный тег — `400`. |
| `POST /profile/me/media?blur=false` | Сырые байты файла, до 25 МБ. Картинок и видео не больше 10; один звук заменяет предыдущий. `415` для неподдерживаемого типа, `422` если обработка не удалась, `400` при достижении предела. |
| `PUT /profile/me/media/order` | `{"urls": ["..."]}` в новом порядке. |
| `DELETE /profile/me/media?url=&index=` | Удаляет одну картинку или видео. `index` необязателен. `404`, если элемента нет. |
| `DELETE /profile/me/audio` | Убирает звук. |
| `PATCH /profile/me/media/blur?url=&blur=true&index=` | Ставит флаг размытия. |
| `POST /profile/me/forms` | `{"value": "my-link"}` либо `{"value": null}`, чтобы получить ссылку. Своя ссылка — 2–48 символов, строчные буквы и одиночные дефисы, без цифр. Сгенерированная ссылка — UUID. У аккаунта может быть 8 ссылок. |
| `POST /profile/me/forms/{slug}/regenerate` | Заменяет сгенерированную ссылку. |
| `PUT /profile/me/forms/{slug}/primary` | Делает эту ссылку той, что возвращается как `form`. |
| `DELETE /profile/me/forms/{slug}` | Удаляет одну ссылку. |

Ошибки ссылок: `form_invalid` (`400`), `form_taken` (`409`), `form_limit` (`400`), `form_not_found` (`404`).

**Лента**

`POST /feed/search` принимает анонимный вызов или подпись чтения. Тело:

```json
{
  "seen_ids": ["публичный id"],
  "requires": ["tag"],
  "excludes": ["tag"],
  "bonus": ["tag"],
  "abonus": ["tag"]
}
```

Ответ — до 20 публичных анкет, сначала более новые. `seen_ids` — публичные id уже показанных анкет; неизвестные id пропускаются. Своя анкета и люди, с которыми уже есть рукопожатие, не попадают в выдачу. Анкета попадает в ленту, если у неё есть текст, тег, медиа, звук или публичный контакт.

`GET /feed/form/{slug}` возвращает одну публичную анкету. `404` с текстом `form_not_found`, если ссылки нет, она неверная или аккаунт заблокирован. Здесь то же правило: анонимно или подписью чтения.

Публичная ссылка открывает веб-клиент на `/netlazy/feed?form={slug}`.

**Входящие.** `GET /inbox` — чтение. Изменения рукопожатия идут по цепочке. Создание ещё требует proof of work.

| Метод и путь | Тело и результат |
| --- | --- |
| `GET /inbox` | Список элементов входящих. |
| `POST /inbox/handshakes` | `{"receiver_id", "type", "offered_contact", "message"}`. `receiver_id` — публичный id анкеты. `type` — `share`, `exchange`, `demand` или `mutual`. Для `share`, `exchange` и `mutual` нужен `offered_contact`. У `demand` его быть не должно. `message` до 100 символов. |
| `POST /inbox/handshakes/{id}/resolve` | `{"status": "accepted"\|"declined", "returned_contact"}`. Разрешить ожидающий элемент может только получатель. Принятие `demand`, `exchange` или `mutual` требует `returned_contact`. Принятие `share` его не принимает. Отклонение скрывает элемент у получателя. |
| `POST /inbox/handshakes/{id}/read` | Отмечает элемент прочитанным для того, кому его ещё нужно увидеть: получателю, пока он ожидает, и отправителю после принятия или отклонения. |
| `DELETE /inbox/handshakes/{id}` | `204`. Скрывает элемент у вызывающего. Запись удаляется, когда её скрыли оба. Отправитель не может отозвать ожидающие `exchange`, `demand` или `mutual`. |

`404` с текстом `profile_not_found` значит, что публичный id неизвестен. Отправка себе — `400` с текстом `Cannot send handshake to self`. Повторная пара обновляет уже существующий ожидающий или отклонённый элемент, кроме отказа, который этот же получатель уже сделал.

Элемент входящих выглядит так. `created_at` и `updated_at` — время рукопожатия. `offered_contact` и `returned_contact` — значения, которые два человека сами решили показать; это отдельно от списка публичных контактов.

```json
{
  "id": "id рукопожатия",
  "type": "exchange",
  "status": "pending",
  "is_sender": true,
  "is_read": false,
  "offered_contact": "me@example.com",
  "returned_contact": null,
  "message": null,
  "created_at": "2026-10-15T00:00:00+00:00",
  "updated_at": "2026-10-15T00:00:00+00:00",
  "profile": { }
}
```

`profile` — публичная анкета.

**Уведомления.** Они уходят, когда для аккаунта создают или обновляют запрос `share`, `exchange` или `demand`. `mutual` подчиняется переключателю exchange. Текст — тип запроса на языке устройства. Контакты и необязательное сообщение в уведомление не попадают. Закрытая вкладка сайта уведомление всё равно получает.

Windows и остальные браузеры используют Web Push. Приложение Android использует push Android. Браузер на Android тоже использует Web Push, а система показывает его как уведомление Android. Каждое устройство хранится отдельно.

`GET /push/preferences` — чтение. Изменение настроек или подписки устройства — запрос по цепочке. `GET /push/key` без подписи. Если настроек ещё нет, все переключатели включены.

| Метод и путь | Тело и результат |
| --- | --- |
| `GET /push/key` | `{"public_key"}`. Несжатый ключ P-256 в base64url для `PushManager.subscribe`. |
| `GET /push/preferences` | `{"enabled", "share", "exchange", "demand", "lang"}`. |
| `PUT /push/preferences` | Тот же объект. `lang` — `en`, `ru`, `pt`, `zh`, `ja` или `ko`. |
| `POST /push/subscriptions` | `204`. Регистрирует одно устройство. |
| `DELETE /push/subscriptions` | `204`. Удаляет одно устройство. Тело — `{"endpoint"}` или `{"token"}`. |

```json
{
  "platform": "windows",
  "transport": "webpush",
  "endpoint": "https://push.example/subscription",
  "p256dh": "base64url",
  "auth": "base64url",
  "open_path": "/netlazy/inbox",
  "origin": "https://example.com",
  "lang": "ru"
}
```

`platform` — `windows`, `android` или `web`. `transport` — `webpush` или `fcm`. Для Web Push нужны `endpoint`, `p256dh` и `auth`, а хост endpoint должен быть известным сервисом push. Регистрация приложения Android отправляет `transport: "fcm"` и `token` вместо этих трёх полей. `open_path` — путь того же сайта, который открывается из уведомления.

Доставка в приложение Android читает `FCM_SERVICE_ACCOUNT` (путь к файлу или JSON аккаунта). Без него токены Android сохраняются, а Web Push продолжает работать. `VAPID_PRIVATE_PEM` заменяет ключ, который сервер иначе хранит для Web Push. `VAPID_SUBJECT` — контакт `mailto:` в токене Web Push.

**Теги, состояние и веб-клиент**

| Метод и путь | Результат |
| --- | --- |
| `GET /tags/search?q=` | Каталог тегов без подписи. Пустой `q` возвращает теги для просмотра. У элемента есть `name`, `aliases`, `hidden` и `i18n`. |
| `GET /api/health` | `{"status": "ok", "auth_type": "per-request-signature", "database": "connected"}` либо `503`, если база недоступна. |
| `GET /api/ui` | `{"interface_version": "1"\|"2"}`. |
| `GET /api/app-version` | `{"version", "url"}` для нативной сборки. |
| `POST /security/ban?user={user_id}` | Только для администратора, заголовок `X-Admin-Key`. Это не маршрут клиента. |

### Минимальный клиент

1. Создайте две пары ключей и зарегистрируйтесь с proof of work. Сохраните `user_id` и `genesis_anchor`.
2. Чтение подписывайте `PQDA-READ-v1`. Изменения подписывайте `PQDA-v1` и текущим якорем, затем заменяйте якорь значением из `X-Next-Anchor`.
3. При `409` обновите якорь и один раз повторите этот цепочечный запрос с новым nonce и временем.
4. Список людей берите через `POST /feed/search`. Возвращённые `id` передавайте обратно в `seen_ids`. Одного человека открывайте через `GET /feed/form/{slug}` или начинайте рукопожатие с его `id`.
5. Медиа расшифровывайте ключом `media_key`. У чужой анкеты не ждите `user_id`, приватных контактов и даты создания.
